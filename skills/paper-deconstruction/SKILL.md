# paper-deconstruction

把一篇论文当成一个**故事 + 工程**的复合物来读。讲师 (ViLT 论文精读) 的核心方法论是五阶法:

```
结构 → 故事 → 拆解 → 评价 → 视觉化
```

前四阶产出 "故事 + 工程" 的文字理解, 第五阶把它装配套图 (论文原图截图 + 自定义图), 产出一份带视觉证据的精读笔记。

---

## 何时激活

- 用户给一篇论文 PDF/链接/视频, 要求"精读"、"讲清楚"、"组会汇报"、"我应该 follow 哪个方向"
- 用户问"这篇论文到底做了什么 / 为什么 work / 有什么坑可以挖"
- 用户要写综述、找课题、写 related work
- **不**适用于: 用户只想速览结论、跑 baseline、看具体实现细节(切到代码阅读 skill)

---

## 五阶法骨架 (结构 → 故事 → 拆解 → 评价 → 视觉化)

四阶法产出的是 "故事 + 工程" 的文字理解。视觉化阶把这份理解变成可被快速浏览的视觉资产 —
**配图不是装饰, 是结构化理解的视觉证据**。每张图都要回答 "这图在讲什么" 的问题。

| 阶段 | 产出 | 配图 | 工具 |
|---|---|---|---|
| 1. 结构 (2-3 min) | 章节地图 + 非典型标注 | 章节地图 (画) | `excalidraw-diagram` |
| 2. 故事 (5-10 min) | 痛点 + 前人 + 卖点 | 时间线 (画) | `excalidraw-diagram` |
| 3. 拆解 (15-30 min) | 六块拆解 | 每块 1 张图 (截/画) | `pdf2png` + `excalidraw-diagram` |
| 4. 评价 (5 min) | 5 维评分 | 雷达图 (画) | `excalidraw-diagram` |
| **5. 视觉化 (5 min)** | **视觉资产清单 + 封面** | **统一装配套图** | **两者都用** |

何时画 vs 何时截图: 详见 `references/visual-assets.md`。一句话口诀 — **作者画过且画得好的就截图, 自己二次组织的就画**。

### 阶段 1: 结构 (2–3 min)

先把整篇论文的章节地图画出来, 标注"非典型"的部分:

- 标准顺序: 摘要 → 引言 → 相关工作 → 方法 → 实验 → 结论
- **找异常**: ViLT 的相关工作 2 页 (综述味), 方法 1 段, 实验 3 页 — 这种"方法短/实验长"几乎都是 SOTA 论文的标志
- **看贡献列表**: 论文末尾的 "Contributions" 段或摘要末尾, 通常 3 条

→ 产出: 5–8 行的结构图 (excalidraw) + 一句"为什么这么组织"。

### 阶段 2: 故事 (5–10 min)

把论文当成一个"作者写给审稿人的 PPT"来读, 提取**叙事主线**:

1. **痛点**: "天下苦 X 久矣" — 这篇论文到底在解决谁的什么不爽?
2. **前人做法**: 按时间线列 3–5 个代表性工作, 标注每个的局限
3. **本文卖点**: 一句话, 写进标题副标题的那种
4. **故事走向**: 作者是"先抛结果再讲方法"还是"先讲方法再抛结果"?

→ 产出: 1 段"故事梗概" + 1 张时间线 (excalidraw)。

### 阶段 3: 拆解 (15–30 min, 主体)

按"输入 → 模型 → 损失 → 训练技巧 → 数据 → 实验"六块拆。每块都问 5 个固定问题 (见 `references/procedures.md`):

| 块 | 关键问 | 推荐配图 |
|---|---|---|
| 输入 | 怎么从原始数据变到模型输入? 哪些预处理可以砍? | 预处理流程 (画) |
| 模型 | 图 N 抄下来, 照着每个模块问"为什么需要它" | **论文 Fig 截图优先** |
| 损失 | 主 loss + 辅助 loss, 每个 loss 在拉什么信号? | 信号流 (画) |
| 训练技巧 | 数据增强 / 正则 / 调度 / trick — 这些都是 follow 论文的"导火索" | 表格即可, 不用图 |
| 数据 | 预训练集多大? 下游几个? 是不是常规组合? | **论文饼图/条形图截图** |
| 实验 | 表格按列看 (baseline / 自己的 / 消融), 不按行看 | **论文主表 + 消融截图**, 速度曲线截图 |

→ 产出: 6 个小节, 每节 3–5 句 + 1 张图。

### 阶段 4: 评价 (5 min)

按五个维度打 0/1/2 分, 写出"是否值得 follow":

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 故事 | 流水账 | 有主线 | 卖点鲜明, 节奏强 |
| 方法 | 缝合 | 局部创新 | 全新框架 |
| 实验 | 不充分 | 常规 | 全面且诚实 |
| 代码 | 不开源 | 有但难跑 | 一行复现 |
| 留白 | 没空间 | 一些小坑 | 留了一堆方向可做 |

→ 产出: 评分表 + 雷达图 (excalidraw) + 1 段"我接下来要不要 follow"。

### 阶段 5: 视觉化 (5 min) — 装配套图

把前 4 阶散落的图组装成完整笔记的视觉资产:

1. **生成视觉资产清单** (放在笔记开头, 列出所有图 + 出处)
2. **统一图片 alt + caption** (alt 写 "图源: 论文 Fig 3, 讲的是什么")
3. **按章节顺序排版** (图随文走, 不要堆在文末)
4. **生成封面** (调 `social-cover-maker`, 一张主图 + 一张方形)
5. **避免 5 类配图错误** (见 `references/visual-assets.md` 第 5 节)

→ 产出: 1 份带完整配图的精读笔记 + 1 张封面。

**最少配图集 (6 张)**: 章节地图 / 时间线 / 模型架构 / 数据分布 / 主表 / 雷达图。
**上限 (9 张)**: 加痛点分类 / 消融图 / Follow 路线图。少于 5 张通常意味着"信息密度低"。

## 核心思维模型 (讲师反复强调)

1. **"N 大痛点" 模式**: 每个 SOTA 论文都先列 2–3 个老方法的痛点, 再提出自己的解法。精读时, 痛点列表决定你能不能 30 秒讲清楚"这篇论文做了什么"。
2. **"X-free 标题" 套路**: anchor-free, BN-free, NMS-free, convolution-free, region-free。**这类标题 = 砍掉一个常用组件 + 性能不掉**。看到一个 X-free 标题, 问"砍了什么 + 为什么能砍"。
3. **思想溯源**: ViLT 不是凭空来的, 是 ViT 在多模态的"手快扩展"。精读时, 永远问"这个 idea 最早出现在哪篇"。这决定你的创新空间。
4. **卖点 > 分数**: ViLT 性能不是 SOTA, 但卖点"1000× 加速"足够强。讲师原话: "性能别做太满, 留给后人 follow。" — 留白是影响力的来源。
5. **"端到端" 是深度学习的价值标准**: 任何"线下抽特征存硬盘"的方案, 都要追问"上线能跑吗"。讲师把这条当成 1/2 个痛点, 反复出现。
6. **写综述 = 找痛点 + 找题目**: 讲师强烈建议初入领域者写综述, 不是为了发表, 是为了**"把当前领域的方法分类"**。分类图 (如 ViLT 的 Fig 2) 是综述里被引用最多的图。
7. **故事 vs 实验的"印象分"**: 同样结果, 会讲故事 (3 个贡献 + 卖点放大 + 数据增强消融) 的论文印象分高 2 档。写论文时, 留 1–2 段做"卖点"叙事。
8. **代码必须开源**: 否则影响力打 5 折。讲师原话: "毋庸置疑, 他们必须是要把这个代码放出来的, 否则这个影响力肯定就大打折扣了。"

## 输出格式

**两档输出**, 接到任务先问"写给谁":

| 输出 | 用途 | 模板 | 配图数 | 自画 : 截图 |
|---|---|---|---|---|
| **学术笔记** | 给同行 / 自己未来翻 / 组会汇报 | `templates/output-template.md` | 5-9 张 | 截图为主 (4:5) |
| **公众号 post** | 给公众号 / 知乎 / 小红书读者 | `templates/wechat-post-template.md` | 6-8 张 | **自画为主 (4:3)** |

**同一篇论文可以同时产出两份** — 学术笔记定结构, 公众号 post 重叙事。两者共享前 4 阶分析, 第 5 阶视觉化时按目标读者分流。

### 学术笔记格式 (写进 `templates/output-template.md`)

**每节至少 1 张配图 (论文图截图 / 自定义 excalidraw), 全文 5-9 张, 不少于 5 张。**

```markdown
# 《<论文标题》》精读笔记

**一句话卖点**: <20 字内>
**结构特点**: <非典型章节>
**性能坐标**: <state-of-the-art 在哪几个任务 / 留白在哪>
**视觉资产**: <列出本笔记所有图 + 出处>

## 1. 故事 (痛点 + 前人 + 卖点)
## 2. 方法 (输入 / 模型 / 损失 / 训练技巧)
## 3. 实验 (数据集 / 主表 / 消融)
## 4. 评价 (5 维评分)
## 5. 接下来要不要 follow / 怎么 follow
```

### 公众号 post 格式 (写进 `templates/wechat-post-template.md`)

**6 段叙事骨架**, 每段过渡用 `---` 分隔:

```markdown
# <一个反直觉的判断句>: <核心卖点压缩成 1 句>

> 一篇 arXiv:<编号>, <月日> 才挂出来的工作。
> <数字卖点>。

## 一个反直觉的小问题      ← 钩子段 + 自画对比图 (必有)
## 痛点: 慢三件套           ← 文字密度, 可选截图
## 核心方案                 ← 论文架构图截图 + 自画工程取舍图
## 实验                     ← 表格, 无图
## 趋势 / 思想溯源          ← 自画 X-free 时间线 (必有)
## 写在最后                 ← 回扣钩子 + 自画 follow 路线图 (必有)
```

**自画图必有 4 张**: 钩子图 / 工程取舍图 / X-free 时间线 / follow 路线图。
**截图必有 1 张**: 论文架构图 (Fig 3 通常)。
详见 `templates/wechat-post-template.md` 和 `references/visual-assets.md` 第 8-13 节。

## 工作流伪代码 (五阶法)

```
read(paper) →
  1. structure(paper)        # 2 min, 章节地图 (画)
  2. extract_story(paper)     # 5 min, 痛点 + 时间线 (画)
  3. deconstruct(paper)       # 20 min, 六块拆解 + 每块配图 (截/画)
  4. evaluate(paper)          # 5 min, 5 维评分 + 雷达图 (画)
  5. visual_assets(notes)     # 5 min, 装配套图 + 视觉资产清单 + 封面
write(notes, template)
```

## 验证回路

- 写完笔记后, 拿 30 秒给同行讲一遍这个论文 — 能否讲清?
- 拿"我接下来要不要 follow"这个判断去对 author 自己的 future work 段, 看是否对得上。
- 拿"分类图" (类似 ViLT Fig 2) 倒推作者的综述能力 — 这决定了相关工作段是否值得借鉴。

## 评估用例

`evals/evals.json` 里有 8 个测试 case, 覆盖:

- 触发: 直接请求精读 / 改述请求 (paraphrase)
- 不触发: 无关任务 (React 组件) / 实现细节 (PyTorch 代码)
- 证据查找: X-free 套路 / 算力细节 (V3_39)
- 工具调用: 30 项 checklist
- 有尊严的拒绝: 视频里没讲 diffusion

跑这些 case 验证 skill 是否按预期工作。`validate_book_skill.py` 是结构层 validation, evals 是行为层 validation, 两者结合才算完整。

## 常见错误 (避坑)

| 错 | 为什么 | 怎么改 |
|---|---|---|
| 一上来就读方法 | 不知道作者要解决什么, 抓不到卖点 | 先读摘要 + 引言, 再读方法 |
| 表格按行读 | 拿不到 baseline 横向对比 | 表格按列读: 自己的 vs 每种 baseline |
| 跳过相关工作 | 错过作者的"分类视角" — 这是综述最值钱的图 | 至少扫一遍, 找"分类图"或"时间线图" |
| 把未来工作当真 | 写未来工作 = 给别人留坑, 不是作者真要做 | 当成"题目来源", 但要快 |
| 看完不写笔记 | 1 周后忘掉 80% | 强制写 5–8 段, 每段不超过 5 句 |
| 不看消融实验 | 消融告诉你哪个 trick 真有用 | 主表 + 消融 = 是否 follow 的决策依据 |

---

## 何时不要用这个 skill

- 论文是数学证明 (需要 proof-by-proof 的方法, 这里的"故事"视角失灵)
- 论文是系统/HCI (实验方法学不同)
- 论文是纯 benchmark (没故事可挖)
