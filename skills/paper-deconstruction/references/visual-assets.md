# visual-assets.md — 精读笔记的视觉资产选择

把"配图"从可选动作升格为产出的一部分。每张图都要回答 "这图是讲什么" 的问题,
不要为了好看而堆图。

---

## 1. 总原则:画 vs 截

| 想要表达的内容 | 选 excalidraw 画 | 选 PDF 截图 | 备注 |
|---|:---:|:---:|---|
| 作者原创的架构图 / 算法框图 | ✗ | ✓ | 截图比复刻更准 |
| 实验主表 / 消融表 | ✗ | ✓ | 表格是论文原作,截图最准 |
| 实验结果曲线 / 散点 | ✗ | ✓ | 同上 |
| 章节地图 / 阅读路径 | ✓ | ✗ | 自己组织的二次理解 |
| 前人时间线 / 痛点分类 | ✓ | ✗ | 二次归类,作者图没有 |
| 方法对比矩阵 | ✓ | ✗ | 自己做的横评 |
| 数据流程 / token 化过程 | ✓ | ✗ | 论文常不画细 |
| 训练流程 / 调度曲线 | ✓ | ✗ | 二次抽象 |
| 5 维评分雷达图 | ✓ | ✗ | 自己评价,作者没图 |
| Follow 路线图 | ✓ | ✗ | 自己规划,作者没图 |

**判断口诀**:作者已经画过且画得好 → 截图;你需要把多个信息二次组织 → 画。

## 2. 工具选择

| 工具 | 用途 | 调用方式 |
|---|---|---|
| `excalidraw-diagram` | 自定义图表 (流程 / 分类 / 时间线 / 雷达) | `/excalidraw-diagram` |
| `pdf2png` | 论文 PDF 任意页 → PNG 截图 | `/pdf2png` 或 `pdftoppm` |
| `lovstudio-pdf2png` | 同上,多页批量 | `/lovstudio-pdf2png` |
| `repo2diagram` | 复现论文代码时画代码结构 | `/repo2diagram` |
| `social-cover-maker` | 笔记封面 (公众号 / 小红书) | `/social-cover-maker` |

### 截图操作要点

- 用 `pdftoppm -r 200 -f N -l N input.pdf page` 把第 N 页导出为 200dpi PNG
- 用 `sips -c 800 600 page.png --out cropped.png` 裁剪到目标区域
- 截图后在文中用 `![描述](path)` 引用, alt 文字要写清 "图来自论文 X 段,讲的是什么"
- 引用论文图时, 在 caption 里注明来源: "图源: 论文 Fig 3, 2026"

### Excalidraw 操作要点

- 单个图表达一个核心论点, 不要塞 3 个 idea
- 文字尽量少, 留白多
- 用 1 个主色 + 1 个强调色, 不要彩虹
- 导出 `.excalidraw` 源文件保留, 渲染成 SVG/PNG 用于发布
- 参考 `excalidraw-diagram` skill 的 `color-palette.md` 保持色彩一致

## 3. 四阶段配图建议

### 阶段 1: 结构

| 输出 | 形式 | 工具 |
|---|---|---|
| 章节地图 (5-8 行结构图) | excalidraw 树状/分层 | excalidraw-diagram |
| 论文图表清单 (Fig X 讲 Y) | markdown 表格, 不必画 | — |

**最少 1 张图**: 章节地图,放在"写在前面"或单独一节。

### 阶段 2: 故事

| 输出 | 形式 | 工具 |
|---|---|---|
| 前人时间线 | excalidraw 时间轴 | excalidraw-diagram |
| 痛点分类图 (N 大痛点) | excalidraw 卡片矩阵 | excalidraw-diagram |
| 卖点对比 (旧 vs 新) | excalidraw 双栏 | excalidraw-diagram |

**最少 1 张图**: 时间线。痛点图是加分项。

### 阶段 3: 拆解 (主体, 6 块各 1 张图)

| 块 | 配图 | 形式 / 工具 |
|---|---|---|
| 2.1 输入 | 预处理流程图 | excalidraw 流程 |
| 2.2 模型 | 架构图 | **论文 Fig 截图优先**,作者没图再画 |
| 2.3 损失 | 公式/信号流向 | excalidraw (信号流) 或公式 markdown |
| 2.4 训练技巧 | 表格 | markdown, 不画图 |
| 2.5 数据 | 数据规模/分布 | **论文饼图/条形图截图优先** |
| 2.6 实验 | 主表 + 消融 + 速度曲线 | **论文表格/曲线截图**, 关键 |

**最少 4 张图**: 模型架构、数据分布、主表、速度曲线。这四张是"工程 + 故事"的核心证据。

### 阶段 4: 评价

| 输出 | 形式 | 工具 |
|---|---|---|
| 5 维评分雷达 | excalidraw 雷达图 | excalidraw-diagram |
| 总分 | 数字 + 一句话 | — |

**最少 1 张图**: 雷达图,把评价可视化。

### 阶段 5: Follow (可选)

| 输出 | 形式 | 工具 |
|---|---|---|
| Follow 路线图 | excalidraw roadmap | excalidraw-diagram |

## 4. 一篇精读笔记的最小配图集

按 "足够 + 不堆" 的原则, 一篇精读笔记配图集:

| # | 图 | 来源 | 必选/可选 |
|---|---|---|:---:|
| 1 | 章节地图 | 画 | 必选 |
| 2 | 前人时间线 | 画 | 必选 |
| 3 | 模型架构图 | 截图/画 | 必选 |
| 4 | 数据规模/分布 | 截图/画 | 必选 |
| 5 | 主表 (实验) | 截图 | 必选 |
| 6 | 5 维评分雷达 | 画 | 必选 |
| 7 | 痛点分类 / 卖点对比 | 画 | 可选 |
| 8 | 消融图 / 速度曲线 | 截图 | 可选 |
| 9 | Follow 路线图 | 画 | 可选 |

**6 张是基线, 9 张是上限。少于 5 张通常意味着"信息密度低"。**

## 5. 配图常见错误

| 错 | 后果 | 怎么改 |
|---|---|---|
| 把论文原图截出来但 alt 是 "image1" | 读者看不懂, 检索不到 | alt 写 "图源: 论文 Fig 3, 输入预处理流程" |
| 截图分辨率太低 | 缩略图糊 | 200dpi 起, 关键图 300dpi |
| 配色花哨与笔记主题不符 | 读者注意力被分散 | 用笔记统一的设计系统, excalidraw 用同色板 |
| 把多张论文子图拼成一张 "大图" | 论文里是独立的, 拼起来误导 | 要么单独截, 要么自己重画 |
| 配图与文字描述脱节 | 读者不知道图在哪一节 | 紧跟对应小节, 标题写在图下方 |
| 重复画论文里已有的图 | 多此一举 | 截图优先, 只在需要二次组织时画 |
| 视觉资产目录不放进笔记 | 读者看不到全景 | 在笔记开头加"视觉资产清单"段 |

## 6. 视觉资产清单 (笔记模板用)

笔记产出时, 在开头加这段:

```markdown
## 视觉资产清单

| # | 资产 | 形式 | 用途 |
|---|---|---|---|
| 1 | 章节地图 | excalidraw | 标注非典型章节 |
| 2 | 前人时间线 | excalidraw | 痛点 + 前人局限 |
| 3 | 模型架构图 | 论文 Fig 截图 | 方法段核心 |
| 4 | 数据规模图 | 论文饼图截图 | 数据段核心 |
| 5 | 实验主表 | 论文 Tab 截图 | 实验段核心 |
| 6 | 5 维评分雷达 | excalidraw | 评价段可视化 |
```

清单本身不是图, 是 "图的目录", 让读者先看全景再读细节。

## 7. 完整工作流伪代码 (更新版)

```
read(paper) →
  1. structure(paper)        # 2 min, 章节地图 (画)
  2. extract_story(paper)     # 5 min, 痛点 + 时间线 (画)
  3. deconstruct(paper)       # 20 min, 六块拆解 + 每块配图 (截/画)
  4. evaluate(paper)          # 5 min, 5 维评分 + 雷达图 (画)
  5. visual_assets(notes)     # 5 min, 装配套图 + 视觉资产清单
write(notes, template)
```

第 5 阶做的是:
- 检查每张图都有 alt + caption + 出处
- 装配套图, 按笔记章节顺序排列
- 在笔记开头加"视觉资产清单"段
- 生成封面 (调 `social-cover-maker`)

## 8. 两种输出模式 — 学术笔记 vs 公众号 post

**同一篇论文, 走五阶法走两遍**: 学术笔记定结构, 公众号 post 重叙事。两者用不同的视觉资产策略。

| 维度 | 学术笔记 | 公众号 post |
|---|---|---|
| 模板 | `templates/output-template.md` | `templates/wechat-post-template.md` |
| 长度 | 1-2 页 | 3-5 屏 |
| 配图数 | 5-9 张 | 6-8 张 |
| 自画 : 截图 | **截图为主** (4:5) | **自画为主** (4:3 或 4:4) |
| 钩子图 | 无 | **第 1 屏必有** |
| 收尾图 | 雷达图 | **X-free 时间线 + follow 路线图** |
| 命名 | `assets/<slug>/` | `assets/<slug>-wechat/` |

**判断依据**: 写给同行 / 自己未来翻 → 学术笔记; 写给公众号 / 知乎读者 → 公众号 post。两者可以并存, 同一论文可以同时产出两份。

## 9. 钩子图模式 (公众号专属)

公众号 post 的第 1 屏配图叫"钩子图", 决定读者留不留下。**必须是自画图, 不要用论文截图**。

### 钩子图的 3 种范式

| 范式 | 用法 | 视觉元素 |
|---|---|---|
| **旧 vs 新 对比** | 当老做法存在但被默认接受时 | 左右双栏, 左侧灰色"旧", 右侧亮色"新", 中间一个加粗箭头 |
| **流程对比** | 当新方法把多步合一时 | 上方多个串行小框 + 下方一个并行大框, 标注时间差 |
| **数字鸿沟** | 当卖点是"数字碾压"时 | 两个柱子或两个圆, 大小对比强烈, 标注倍数 |

### 钩子图配色规则

- 1 主色 (深蓝 / 深紫) + 1 强调色 (橙 / 红)
- 旧方法用灰色, 新方法用强调色 — **视觉上读者立刻知道哪个是被吐槽的**
- 字体粗细对比强, 主标题加粗到 18pt 以上

### 钩子图与首段文字的配合

钩子图必须紧跟在"反直觉问题"展开后, **在"这就是 X 的痛点"那句之后立刻插入**。文字 → 钩子句 → 钩子图 → 引出新论文。

例 (locate-anything 范式):
```
我们让 VLM 在图里把那只猫圈出来。
<2-3 段问题展开>
**这就是 NTP 在 grounding 上的根本痛点。**

![NTP vs PBD 对比](assets/locate-anything-wechat/01_ntp_vs_pbd.png)

NVIDIA 5 月 27 日挂出的 LocateAnything, 干的就是这件事: ...
```

## 10. 收尾路线图模式 (公众号专属)

公众号 post 的趋势段必须有 2 张自画图: **X-free 演进时间线** + **N 个 follow 方向路线图**。

### 10.1 X-free 演进时间线

把"思想溯源"做成视觉时间线:
- 横轴: 年份 (3-5 个时间点)
- 每个点: 一个 X-free 工作 (anchor-free / region-free / serial-free / ...)
- 高亮: 本文所在的时间点, 用不同形状/颜色
- 标注: 每代砍了什么, 性能涨了多少

**作用**: 让读者立刻知道"这工作不孤, 是 lineage 上的下一步"。

### 10.2 N 个 follow 方向路线图

把 Limitation + 自己推测的 follow 方向, 画成放射状路线图:
- 中心: 本文方法的缩写
- 周围 4-6 个分支: 每个分支是一个 follow 方向
- 每个分支标注: 1) 方向 (3-5 字) 2) 难度 (低/中/高) 3) 算力需求 (小/中/大)

**作用**: 读者读完, 知道"我可以接着做什么"。

### 收尾路线图 ≠ 学术笔记的雷达图

学术笔记用雷达图给"5 维评分"。公众号 post 用路线图给"5 个 follow 方向"。**前者是评价, 后者是召唤**。

## 11. 公众号 post 的配图节奏 (7 张图的位置)

按叙事顺序, 每张图的"必要性 + 位置 + 类型":

| 段 | 图 | 类型 | 必要性 |
|---|---|---|:---:|
| 1. 钩子 | `01_hook.png` (对比图) | 自画 | ✓ 必有 |
| 2. 痛点 | `figXX_pain.png` (论文 Fig 支撑某个痛点) | 截图 | 可选 |
| 3. 方案 (架构) | `figYY_arch.png` (论文架构图) | 截图 | ✓ 必有 |
| 3. 方案 (工程取舍) | `02_modes.png` (推理模式 / 工程权衡) | 自画 | ✓ 必有 |
| 3. 方案 (数据) | `figZZ_data.png` (数据分布饼图) | 截图 | 可选 |
| 5. 趋势 | `03_xfree_timeline.png` (X-free 演进) | 自画 | ✓ 必有 |
| 6. 收尾 | `04_follow_roadmap.png` (5 个 follow 方向) | 自画 | ✓ 必有 |

**自画 4 张, 截图 3 张 = 7 张**。最少 5 张 (砍 2 个"可选"截图), 最多 8 张 (加 1 张消融对比)。

## 12. excalidraw skill 调用速查

5 张自画图的调用模板 (按公众号配图节奏):

```bash
# 1. 钩子图: 旧 vs 新 对比
/excalidraw-diagram "<旧做法名> vs <新方法名> 的对比图, 左侧灰色显示串行/复杂流程, 右侧高亮色显示并行/简化流程, 中间加粗箭头标注 <数字>× 加速"

# 2. 推理模式 / 工程取舍图
/excalidraw-diagram "<方法名> 的 N 档模式: <模式 1> <模式 2> <模式 3>, 每档标注速度 / 精度 / 适用场景"

# 3. X-free 演进时间线
/excalidraw-diagram "<领域> 的 X-free 演进时间线, <年 1> <X1-free> → <年 2> <X2-free> → <年 3> <X3-free>, 高亮 <本文> 在 <年 N>"

# 4. follow 路线图
/excalidraw-diagram "<本文方法> 之后的 N 个 follow 方向: <方向 1> <方向 2> <方向 3> <方向 4> <方向 5>, 中心是 <本文方法>, 放射状分布"

# 5. (可选) 5 维评分雷达图
/excalidraw-diagram "5 维评分雷达图: 故事 <分>, 方法 <分>, 实验 <分>, 代码 <分>, 留白 <分>"
```

截图 3 张的调用:

```bash
# 用 pdftoppm 把论文 PDF 第 N 页转成 200dpi PNG
pdftoppm -r 200 -f <N> -l <N> input.pdf page_<N>

# 用 sips 裁剪到目标图区域 (可选)
sips -c <h> <w> page_<N>-1.png --out figXX_<descriptor>.png
```

## 13. 配图 5 + 2 错误 (公众号专属新增)

除了第 5 节的 7 种通用错误, 公众号 post 还有 2 个专属错误:

| 错 | 后果 | 怎么改 |
|---|---|---|
| 钩子图用论文截图 | 读者第 1 屏看到密集文字图, 直接跳过 | 钩子图必须自画, 视觉对比强烈 |
| 收尾段不画路线图 | 读者读完不知道"我能做什么", 转发率下降 | 收尾必有"N 个 follow 方向"路线图 |
