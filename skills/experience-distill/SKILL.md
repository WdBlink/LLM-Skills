# Experience Distill

将任务经历转化为能够改变下一次具体操作的知识。以“触发条件 → 操作 → 证据 → 不适用边界”组织条目；运行流水账只作为证据索引，不直接充当知识。

借鉴 KSI 的任务内提炼、反例对照与面向目标的知识选择，采用当前助手即可完成的轻量流程。无需安装 KSI、启动 Agent 论坛或依赖固定模型。此技能固化提炼方法，不把某次任务的结论变成所有任务的规则。

## 输入与取证

- 优先使用用户指定的任务和材料、当前可见会话、已知产物及其指向的日志。先确认任务目标、实际结果和可读证据范围；不要扫描无关私人会话或整个磁盘寻找素材。
- 先读现有结果摘要与证据索引，再针对关键失败、修复和验收读取原始请求、响应、修改、检查结果。只读核验默认足够，不为复盘重新执行昂贵任务或重放外部副作用。
- 区分原始观察、当时的解释、后来的修订和最终核验。总结文档是取证入口；如果原始证据无法取得，明确标注“仅据总结/会话陈述”。只有叙述时可以整理低置信候选，不能补造日志、引文或验证状态。
- 没有可用的任务材料时，询问一个最小必要输入，例如任务记录或日志路径，不输出通用经验充数。部分缺失只限制相关结论。

## 提炼与反证

围绕会改变行动的事件整理“尝试 → 观察 → 修正 → 检查”，优先寻找重复失败、意外成功、审核分歧、错误归因、恢复丢失和额外成本。不必完整复述时间线。

对候选经验逐项处理：

1. 写出具体触发条件和可执行动作。点名真实操作、接口、数据关系、实验协议或故障模式；删除“认真检查”“合理拆分”等可以用于任何任务的泛泛建议。
2. 把动作与实际证据绑定，说明它解决了哪个问题。只有最终成功，不能证明之前所有改动都有效；多项同时修改时，单项收益仍可能无法归因。
3. 查找相反结果或可使规则失效的条件。否定精确方案及已试参数，不因一次失败就否定整个模型、工具或方法；未试过的相邻方案保持开放。
4. 区分代码/结构正确、语义正确、业务验收通过和效率改善。测试通过只支持所覆盖的性质，单次 accepted 不等于可迁移能力或生产稳定性。
5. 不把同一任务的重试、同源意见的重复、同一摘要的多个副本当作独立验证。允许同一案例支持多条不同机制，但明确共同来源。

保留有信号的少量条目，合并同义内容。不强制凑满数量，也不强制补齐所有类别。可按需要区分可迁移候选、已确认约束、被否定方案、陷阱、检查和待验证实验。

## 每条知识应包含

| 字段 | 内容 |
|---|---|
| 规则 | 在什么情况下，采取哪个具体动作 |
| 适用条件 | 能区分相关与不相关任务的结构、环境或输入条件 |
| 证据 | 实际文件/URL、事件或调用 ID、已知版本，以及观察到的结果；必要时附短原文 |
| 不适用边界 | 已观察反例或推理得出的边界；后者明确标为推断 |
| 检查 | 已执行的验证与结果，或明确标记为待执行的最小检验 |
| 置信度与范围 | 对哪个机制有把握，迁移与因果收益是否仍未验证 |

置信度采用文字说明即可：直接原始证据和对应检查支持局部机制；存在混杂或只有叙述时降低确信程度；未经检验的行动放入候选或后续实验。不要生成缺乏依据的数值概率。

条目写得过泛、反例难以划定，或需要输出样式时，按需读 [示例与输出模板](references/examples.md)。例子只解释写法，不是用户当前任务的证据。

## 交付与复用

- 用户要解释时直接回答；请求沉淀、保存或产物时，优先写一份 Markdown 到用户指定位置或项目现有文档位置，返回链接。无须为提炼新增数据库、索引或多种重复格式。
- 文稿包含简短证据基线、知识条目、重要分歧/失败方案边界、必要的待验证项。调用数、token、费用和时间分别报告，只统计已知范围，保留失败成本；不将调用次数换算成未经记录的费用。
- 用户给定下一项任务时，只选择适用的知识写成短启动备忘录，保留条件与条目 ID。未给定时可以给原任务类型的备忘录，明确适用范围；不要把全部历史塞入下一次上下文。
- 若在更新已有知识，按证据合并、缩小适用范围或标记被替代；不默默覆盖相反证据，不把历史判断当作当前执行指令。
- 提炼或保存知识不等于授权继续原任务、运行新实验、修改源码、发布知识或改写 AGENTS.md/Skill/全局配置。只按当前请求处理；不声称知识已自动加载到未来任务或更新了模型权重。

收尾核对证据链接、条目是否确由证据支持、边界是否真实、检查是否执行过，以及备忘录有无把暂定结论升级为强制规则。说明实际交付与验证限制，满足本次提炼目标后结束。
