# 示例与输出模板

## 从本次长程 Review 中抽取的写法示例

这是来源于 Summer/Kronos 任务的历史示例，用于说明具体程度。原始日志不随技能分发；它不能充当其他任务的验证证据，也不是必须采用的架构。

**泛泛结论**：模型要保持输出一致，注意检查格式。

**条件化规则**：当正文、结构化 claims 和 coverage 表达同一批事实时，让模型只生成事实对象，再由代码派生正文和映射，减少多次生成导致的措辞及编号漂移。

- 观察：历史尝试中，独立正文与 claims 发生漂移；占位符方案又出现不存在的 ID。允许 string 或 fact 的混合 blocks 曾全部输出字符串。
- 修正：改为必需事实对象，并由运行时排版。
- 支持范围：真实输出已验证排版与 canonical 正文一致；后续仍有语义支持缺口，说明机械一致性不能代替语义审核。
- 边界：不同产物需要表达不同内容时，不强制共享一个对象；自由分析文本仍可能包含需审核的新事实。
- 迁移：机制可作为其他结构化写作任务的候选，但整体成本是否降低仍需对照检验。

另一个对照：Supervisor 断线后复用有效 Worker，适用于依赖仍有效的只读步骤；不能直接推出扣款或部署也可以无条件重放。

## 一条知识的简短样式

```markdown
### K1：规则标题
- 规则与适用条件：当……时，执行……
- 证据：实际记录定位；观察……；修正后……
- 不适用边界：……（已观察/推断）
- 检查：已执行……，结果……；或“待执行：……”
- 置信范围：已支持……；尚未验证……
```

编号仅帮助引用。证据不足时删去无法支持的部分，或将整个条目标为候选；不用伪造证据补齐模板。

## 反例处理

| 已知材料 | 应保留的结论 | 不应生成的结论 |
|---|---|---|
| 一个库版本的一条并行恢复路径失败 | 记录版本、触发路径、复现和对应修复 | 这个框架的并行都不可靠 |
| 多处改动后最终验收通过 | 组合改动后的产物通过；可单独验证的机制分别记录 | 每项改动都降低了成本 |
| 审阅材料没有第三方复现信息 | 本次材料不足以确认第三方复现 | 从未有人复现 |
| 只有一次“测试通过”的会话陈述 | 来源为会话陈述，未核验原始输出 | 已独立复现并验证 |
| 同一问题重试七次 | 一个任务的七次尝试 | 七个独立任务都证明规则有效 |

## 启动备忘录

从正文选择与接收任务有关的条目。示例：

> 本任务同时输出结构化事实和正文，优先让同一事实对象派生多种表示（K1）。若两种输出实际承载不同内容，则分别建模。该建议支持机械一致性，不能取代最终语义审核。

不要将示例中的具体工具、调用数量、环境端口或模型搭配自动带入新任务。未知下游任务时标明备忘录面向哪类任务，不宣称适用于一切工作。
