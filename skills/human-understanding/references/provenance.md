# 原帖核对与设计来源

## 核验范围

来源：[Karpathy 原帖](https://x.com/karpathy/status/2105819303471976479)，界面日期为 2026-10-02。2026-10-04 使用用户已登录的 Chrome，通过原生界面读取了完整正文及 [附图](https://x.com/karpathy/status/2105819303471976479/photo/1)。Web 抓取仍返回 403；浏览器实际呈现的原帖是此次核对依据，未用转述文章替代原帖。

## 原帖的具体主张

1. 随着 LLM 能力增强，人会把更多时间用于理解模型输出。模型承担更多基础工作后，人的工作更多走向监督与理解。
2. **写作**：用 ASD-STE100 这一航空维护文档的受控语言规范约束解释。他认为结果更易读；也尝试用“80% of the way to ASD-STE100”软化严格规则。该比例是提示语，没有给出合规度测量方法。
3. **图解/图像**：让模型将说明转成图，可能更容易处理、解析和理解。
4. **网页**：请求 HTML，利用模型前端能力制作交互页面、动画和定制体验。
5. **解释视频**：这是他最看好的形式；举例为特定主题制作 3Blue1Brown 风格的解释视频，用 ElevenLabs 配音，也可寻找使用本地算力的免费替代方案。该示例说明方向，不意味着已提供完整视频工作流。
6. **结尾的原因**：智能与代码逐渐充裕，让大型、定制、用完可丢弃的软件解释产物变得值得制作，鼓励探索以前不值得开发的形式。

帖子的递进语气表达对更丰富解释载体的期待；它没有证明所有问题都应生成网页/视频，也没有建立媒介的普遍效果排名。

## 配图补充了什么

附图是一张 ASD-STE100 概览，展示写作规则与词典两部分、句子改写、动词形式、词条示例和长度限制。图中包括：同一对象用同一词、每词固定含义/词性、操作用主动语态、一个句子通常一个指令、每段一个主题，以及英文操作句 20 词、描述句 25 词、段落 6 句、名词串 3 词等上限示意。

本技能将图中的术语、动词、句长、段落、指令和安全说明转成可执行规则，另加入材料缺失、事实强度与机制解释的处理。中文规则是实践迁移，不属于 ASD-STE100 英文标准；语义不能无损改写时保留原意。附图是原帖的解释材料，不能据此宣称已审阅完整官方标准或产物严格合规。本次未读取官方标准全文。

## 本技能增加的合同

用户于 2026-10-04 要求：先定义理解任务，按理解需要选形式，关键结论绑定原始证据，表达检查与事实检查分开，并明确第一版可不做视频。这些是任务要求，不应归称为 Karpathy 的原帖主张。

理解障碍诊断、15 条语言执行规则中的任务扩展和语义例外、滑块/逐步模拟的设计方法、观察/推断标签、证据字段、Python 检查器、停止条件和验收场景均是针对这些要求的工程编排。“80%”只保留为原帖提示语的来源记录，不作为 Skill 的执行指令或评分。特别是 HTML 教学交互不等同于实验筛选台；临时概念解释无需实验字段。

已读取 [Claude Code 官方 Skills 文档](https://code.claude.com/docs/en/skills#generate-visual-output) 的 Skill 配套脚本生成交互 HTML 模式，仅用于支持实现可行性。
