# Human Understanding

把材料变成读者能够理解、检查和使用的解释：说清关键关系、条件变化的后果、证据边界，以及确实需要读者作出的决定。支持清晰文字、图解和定制交互 HTML；视频不在当前范围。来源记录见 [provenance](references/provenance.md)。

## 判断任务与选择入口

先确定问题、读者背景和材料范围，找出理解障碍。研究/工程结果审阅缺省面向项目负责人回答“发生了什么、证据支持什么、还有什么没证明、需要决定什么”；概念解释围绕机制组织，不强造投入决策。优先从上下文推断，只有不同答案实质改变解释时才澄清。

列出原始材料，必要时读取实验记录、失败回执、评价协议与代码。其他 Agent 的总结只是线索；关键解释回到对应来源。缺来源仍可交付有边界的说明，未读材料不能称为已核验。

**起草和复核前必须读取 [15 条具体表达规则](references/explanation-methods.md#必须执行的15条规则)。** 全文、图标签、HTML 提示和证据卡都执行这些规则。主体、术语、指代、条件、否定、数值、机制中间步骤，以及英文时态/冠词/长度与安全说明要求完整保留；不得用“接近某标准”代替具体操作。规则只在该文件维护。

选择最小有用路径：

- 材料已在当前上下文，短文字即可解释时，直接按规则回答；不为一句解释强制建立 JSON 或状态目录。
- 需要重复读多份材料、绑定来源、组装引用/证据卡、制作可复用比较页面或保存检查结果时，使用下面的 `prepare → 当前宿主判断 → apply → finish` 入口。已有入口覆盖时直接调用，不重写同一套读写/拼装代码。
- 关系图、逐步算法、参数模型等需要新的解释设计时，宿主决定关系和交互，并复用合适的图形工具或已有实现。程序负责共同材料、证据和交付记录；不把开放的解释创作假装成确定算法。

## 脚本入口

Python 3.8+，仅标准库；脚本不调用模型、网络或浏览器。`SKILL_DIR` 为本 Skill 的实际绝对路径，`RUN_DIR` 为本次任务可写目录，运行产物不得存入安装目录。参数、JSON 合同和恢复规则见 [执行合同](references/workflow-contract.md)，只需读取使用合同，无需日常加载全部源码。

```sh
python3 "$SKILL_DIR/scripts/run.py" prepare --source "$RUN_DIR/material.txt" --question "本轮结果支持什么？" --reader "项目负责人" --scope "仅本次提供的材料" --out "$RUN_DIR/request.json"
```

`--source` 可重复，用于 UTF-8 文本、JSON 或已有工具提取的材料。默认总量上限 12,000 字符，可用 `--max-chars` 显式调整到不超过 50,000；超限失败，不静默截断。按需分包时保留范围、反例与未覆盖项。缺来源用 `--missing` 明示；`--format auto|text|diagram|html` 保留用户指定形式。

多项指标/计算值得结构化核对时可传 `--evidence`，复用 [证据合同](references/evidence-contract.md) 和检查器，自动读取其可用本地来源。普通概念图、短解释、公式演示无需 `evidence.json` 或实验字段。网页/文档先通过已有连接器获取合规本地快照，保留来源与获取时间，不强包成脚本 API。

准备脚本输出 `needs_judgment`。当前宿主读取实际请求和表达规则，写出 [合同规定的结构化判断](references/workflow-contract.md#判断文件)：答案、解释段、类型、条件、限制和来源 ID；不转抄原文。必要时用明确标为演示的输入展示“输入→规则→中间状态→结果”。材料不足而无法回答时返回 `needs_input` 和具体缺口；可回答部分则在解释中明确缺失。

```sh
python3 "$SKILL_DIR/scripts/run.py" apply --request "$RUN_DIR/request.json" --decision "$RUN_DIR/decision.json" --out "$RUN_DIR/output"
```

脚本检查绑定、来源变化、字段和引用，复制原始摘录/指标，生成文字或证据比较 HTML，并保留已有缺口。`needs_review` 只表示文件已组装，不表示语义/图形/交互正确。之后实际核对成品，写 `review.json`，再运行：

```sh
python3 "$SKILL_DIR/scripts/run.py" finish --request "$RUN_DIR/request.json" --dir "$RUN_DIR/output" --review "$RUN_DIR/review.json" --out "$RUN_DIR/completion.json"
```

## 按理解障碍选择载体

| 理解障碍 | 产物与必须帮助读者完成的动作 |
| --- | --- |
| 一个结论、少量数字或简单概念 | 短文字、小例子或表格，直接看懂条件和变化 |
| 结构、依赖、空间关系或方案差异 | 图解显示对象、连线含义、关键中间环节；事实/假设区分，数值轴/单位/范围可见 |
| 动态过程、变量变化、多个推演步骤 | 定制 HTML 调参数、逐步推进、暂停/重置，观察状态、图形与解释同步变化 |
| 多实验比较与查证 | 默认脚本 HTML 提供类别筛选、计数、空结果、重置和证据展开；复杂比较按实际需要定制 |

主动考虑能降低理解成本的临时软件，没有大型数据集也可能值得制作。一个滑块或逐步按钮足够时，不加账户、后台或部署。用户指定形式时在该形式内完成；单结论两个指标也无需做 App。

**定制教学 HTML 与图解始终可用。** 先读 [对应解释方法](references/explanation-methods.md)，定义“读者操作什么、观察什么、理解什么”。复用已有工具或最小 HTML/CSS/JS；仅为新的机制/交互编写必要代码。通过 apply 的 `--artifact /绝对路径/explainer.html` 或图文件接入，脚本复制产物并保存审核绑定，不执行或认证自定义代码。

自定义产物内必须首层显示重要限制、模型/演示身份与来源；旁边的 explanation.md 不替代页面内的说明。来源文字必须转义，不能成为 HTML/脚本。图优先 Mermaid/SVG 等合适工具；数据图保留轴、单位和范围，不凭图示添加因果。

HTML 的输入、当前状态和反馈可见，控件有标签、范围、单位，键盘可用；按适用项提供暂停/重置和减弱动态效果。公式/玩具模拟/假设情景与观测区分。实际打开图与页面检查关系、正常/边界/空结果、重置、键盘和小屏；无法执行的检查明确披露。固定筛选模板不能代替动态机制解释。

## 证据和完成标准

关键结论能追到来源、适用条件与限制。实验比较包括实验、基线、方向、单位、样本数/范围、失败与退化；纯概念引用定义/公式/实现，不填造实验字段。观察、推断、缺失、冲突、建议与演示分开。局部改善不能称整体成功，单次不能称稳定或显著，相关不能称因果，不可比条件分开展示。

首层保留会改变判断的限制，细节可展开。程序检查数字、单位、计算和引用的一致性；模型再检查最终答案、正文、标题、图例是否跃迁结论或遗漏限制。源记录通过不代表成品通过，`pass_with_gaps` 不能变成全部已证实。

检查读者是否能跟着例子推演一步，解释为什么或预测条件变化；只重排文字、装饰图或加按钮不算解决理解障碍。程序检查、宿主语义自检和实际交互检查分别记录，自检不得称独立审查。

交付直接回答问题、链接实际产物并给最少使用说明。决策相关时说明选项、取舍和什么新证据会改变建议。完成状态见执行合同；失败或未执行项如实披露，不能凭 JSON 合法宣布完成。行为回归与成本记录见 [验收场景](references/acceptance-cases.md)。

## 出错与恢复

缺文件先补材料；无效判断按具体字段错误修复一次，仍失败保留诊断；证据缺口不靠重复生成解决。输入、规则或实现变化后重新 prepare/判断；不同内容使用新输出目录，原结果不覆盖。同输入同判断重跑可恢复未完成写入。修订最终产物后重新 apply 和复核，旧 review 不能套用。

简单路径不启用模型后端、专用 Agent 或 LangGraph。确需批量/独立审查时才另外接线，并保留相同输入输出及验证范围。
