# Photographer Style

把摄影师的作品规律转成可解释、可执行的照片编辑资产：风格介绍、关键参考图，以及主动模式与微调模式目录下各自独立的 `README.md`。主动模式以人物更好看且符合该风格的审美为目标，默认保留场景地点，允许在同一现场重绘细节、调整美颜、动作、光线与构图；明确要求更换场景地点时才换地点。微调模式只改光影、色调与人脸局部遮瑕。摄影师名字只能作为背景，不能代替具体指令。

当当前用户为某套风格明确配置“以身份为依据的重新拍摄”时，读取该配置及适用范围，沿用已获授权的创作边界，不重复逐项确认。配置可允许背景、服装、妆发、表情姿态、构图与光色重新设计；只有实际列明的项目才适用。不能根据摄影师姓名、参考图片或另一用户的历史设置推断授权。其他风格与微调模式不随之放宽。

## 从已有输入继续

- 只有摄影师姓名：搜索风格拆解视频，优先哔哩哔哩、YouTube；同时寻找可核验的作品图录、官网或访谈作为对照。
- 已有链接或本地视频：直接进入媒体处理；已有文字稿或图片则复用，避免重做上游。
- 已有完成的提示词资产或本地资产目录，用户要求上传、归档或版本管理：直接进入 GitHub 归档阶段，复用已有内容，不重新跑研究或默认重写提示词。
- 只有参考照片与用户理解：先给范围明确的视觉分析与提示词，不虚构视频来源、摄影师身份或转写结果。
- 用户明确说随后补材料：可准备通用流程；具体摄影师的最终判断和实例验证等待材料。姓名不明且无法从上下文确定时再问。
- 目标编辑模型未知时输出通用自然语言；只有模型选择影响实际调用或参数时才澄清。制作提示词本身不包含图像生成、向图像生成服务上传原片或训练模型；GitHub 资产归档按下方独立阶段处理。

## 搜集与本地处理

先验证搜索结果的真实标题、作者、链接和相关性，再选包含作品展示与具体分析的视频。起步用少量高相关来源，按证据缺口补搜，不按播放量判断分析质量。可组合查询“姓名 摄影 风格 分析 / 作品 解读”与“name photography style analysis / visual language”。核对同名摄影师及系列，保留 B 站分 P 信息；搜索摘要不能当作看过视频。

处理视频时读 [references/media-workflow.md](references/media-workflow.md)。下载优先 `yt-dlp`，抽音轨与截帧用 `ffmpeg`，转写用本地开源 Whisper 实现。Apple Silicon 优先考虑 `whisper.cpp`；已有可用后端则复用。Downie 下载好的本地文件也可直接接入。

在用户指定位置保存；未指定时用当前工作区 `generated/photographer-style/<photographer-slug>/<run-id>/`。没有姓名时用中性任务名。运行资料不写进技能目录。保留源文件，继续运行前核验已有产物属于同一视频与时间轴。

以实际输入为准维护以下交付物，不为缺失输入创建伪成果：

- `sources.md`：来源链接、作者、视频 ID/分 P、采用理由、本地文件对应关系；注明下载、字幕/ASR、视觉核验和未完成阶段。
- `media/<source-id>/`：视频、来源元数据、原始字幕或转写、候选联系表与时间记录、选定原始截图。
- `illustrated-transcript.md`：完整文字稿按原时间顺序保留，附近嵌入相关的关键截图和简短图注；分析批注与原话分开。
- `style-analysis.md`：作品范围、用户理解的核对、创作决策规则及其证据、取舍、反例与验证状态。
- `README.md`：该风格的独立介绍，说明作品子集、核心摄影逻辑、人物美感目标、适用范围、两种模式的区别与入口、参考图和来源。归档时位于仓库的 `<style-slug>/README.md`。
- `prompt-assets/主动模式/README.md` 与 `prompt-assets/微调模式/README.md`：两个独立、可直接复制的中文提示词，分别说明保留项、可调整项与上传角色；打开 GitHub 模式目录即可展示内容。默认两版都交付；用户明确只要一种时按指定范围输出。
- `prompt-assets/reference/`：两版共用的关键参考图，以及记录已知来源、原视频时间和裁剪坐标的 `sources.md`。使用单数 `reference`；缺失的来源信息明确注明，不补造。两个模式 README 用相对路径嵌图，交付时保留整个 `prompt-assets/` 目录。仅有参考作品时提供可复用提示词，并说明尚未适配具体原片。

## 从图文证据到编辑提示词

分析与提示词编写时读 [references/style-to-prompt.md](references/style-to-prompt.md)。先看实际图像，再把观点落到可见证据；不能仅从字幕或摄影师声誉猜风格。

在图文分析后、编写提示词前提炼创作决策：摄影师关注什么，遇到什么条件时怎样选择，发生冲突时优先保留什么。用跨作品复现、新情况的生成力和组合辨识度筛选规则；照片可证明视觉结果，意图与制作过程须另有来源，仅由成片推导的规则标为分析假设。将规则及适用边界写入已有 `style-analysis.md`，用于参考选择、正文中的条件式动作与验证；不只增加风格形容词。通用方法保存在本技能，具体摄影师的证据和规则保存在各自风格资产，不自动新建人物扮演技能。

在提示词设计阶段先分析该作品子集适合的原始照片素材：人物数量与景别、身份信息、场景类型、原有光照、构图条件和人物呈现诉求。区分最适合、条件适配与不宜强套的输入，说明依据；将本风格具体的适用条件和不匹配时的处理写进风格介绍及两版可复制正文，不能只放在分析稿或生成失败后的说明里。有原片时先据此选择风格；参考图也须匹配这些条件，没有合适参考可只用原片与完整文字提示词。

有现成参考库并执行生成时，Agent 必须先实际查看全部可用候选，再按当前人物和任务选择主参考与必要辅助，说明取舍和附件角色；不能固定首图或沿用上一人的选图。参考完整性、主辅编号及用途、实际上传顺序记在本次本地运行资料中，不新增常驻系统。可全组上传作候选，但须选主次，不将所有图片平均融合；超过工具容量时先在执行端比较全组，再上传选中项。只有文字、链接或路径不等于生成模型收到图片；执行端负责读取与上传，缺失项如实说明。棚拍创作按人物特点和目标摄影关系匹配，不以原地点、原衣服或原光线为硬条件；保留现场模式继续比较现场兼容性。

关键截图由 Agent 查看候选画面后选择，不让用户重新承担逐帧截图。作品展示、摄影师本人拍摄、解说者仿拍、反例和幕后画面必须区分。字幕中的“这张照片”可能早于或晚于展示画面，要在相邻时间范围核对。

每条用于提示词的核心规律建立“来源或样图 → 可见现象 → 视觉作用 → 编辑动作 → 适用条件”的对应。保留现场的主动模式可以把取景、姿态与场景关系转成同一地点内的重构指令，同时保持人物身份和地点可辨；保留地点不等于禁止重绘现实细节或锁死人物动作。微调模式保留表情、动作、场景、构图和五官结构，仅执行后期光色处理与局部遮瑕。

先吸收来源的核心主张及其摄影逻辑，再将内容、构图、影调、分区色彩之间的因果关系写入两版可复制正文。逐项核对来源重点的落点或未采用理由；分析稿详细而提示词仍是通用修图要求，视为尚未完成转化。

人像任务还要拆解“这个风格里的人物为什么好看”：从样片观察构图与机位、表情眼神、动作与肩颈、发型妆容、光影肤色、肤质修饰和服装等实际相关因素，定义该子集的审美目标。主动模式正文专设“人物吸引力与美化”段，将观察转成具体改善动作，不能止于“适度美颜”。区分可见外观与未知制作过程，不凭成片断言磨皮、整形或妆发手法。

参考资产优先使用清晰的单幅作品；从视频中提取时保留全帧证据，另裁出完整作品区域。避免把教程界面、字幕、仿色练习图或反例混入目标参考集。不得生成、重绘或重新调色来补造“参考作品”。

## GitHub 归档与版本管理

用户要求上传、归档、版本管理，或当前任务已有相关授权时，读 [references/github-archive.md](references/github-archive.md) 并完成本地整理、提交、推送与远端核验。从当前用户指定的位置或已有明确配置确定仓库与本地目录，核对已有克隆的远端；不内置个人资产库。目标尚不明确时先完成本地整理，仅澄清上传所缺的目标。已有授权不重复询问；仅研究或修改技能不自动触发上传。

每个风格使用独立目录与介绍 README，沿用上面的双模式 README 和 `reference/` 布局。整理已有资产时保留原始材料、图片字节与提示词正文，更新文件路径、介绍和链接；只有用户另行要求修订时才改提示词内容。只归档本次授权的最终资产，不把原视频、转写、模型、缓存或未获授权的原片一并推送。

## 完成核验

- 视频可读；文字稿有来源和可对齐的时间戳；抽查开头、中间、结尾的同步与摄影术语。没有运行 ASR 时不称为模型转写。
- 联系表已实际查看；入选截图能看清作品，并且文字指代、时间戳、作品归属一致。Markdown 图片路径可解析；分享时连同图片目录交付。
- 风格结论区分用户观察、解说观点、图像观察与推断；反例或系列差异没有被抹平。
- 创作规则包含触发条件、视觉作用、取舍与失效边界；参考选择和可复制正文有实际落点。材料允许时用未参与提炼的作品检验，并做新情境推演及反例检查；记录失败与未验证项，不能把文字推演称为生成实测。
- 每个风格已在设计时分析适合的原片条件；介绍与可复制正文包含有区别的适用范围、不匹配处理和参考选择依据，不用同一段泛泛的素材要求覆盖所有风格。
- 主动版明确人物要如何变得更好看，相关表情、姿态、发型、光线或肤质指令有样片依据及原片适配条件；改善外观同时保留身份可辨认性，微调版不继承动作、发型或结构重塑。
- 每个风格有独立介绍 README；两个模式 README 能独立使用，均链接 `reference/` 中实际存在的参考图，并说明保留项、可调整项及冲突优先级；主动版没有误带禁止一切动作/场景/构图变化的约束，微调版没有放入这些重构动作。未提供原片或未实际试图时，说明迁移效果尚未验证。
- 执行 GitHub 归档时，确认目标可见性为私有、本次提交范围正确、目录和图片链接可解析、推送后远端提交与文件内容一致，风格与模式目录的 README 可被 GitHub 识别；交付仓库或风格入口及提交版本。只有本地提交时不称为已上传。
- 最终交付链接、实际完成阶段和剩余限制。用户只要某一阶段时交付该阶段，不强制跑完整流程。
