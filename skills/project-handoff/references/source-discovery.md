# 材料发现与历史覆盖

在建立问题框架后、读取正文前使用。这里是宿主适配方法，不是假定所有 Codex 都有某套接口。

## 范围与资产

1. 规范化用户范围的真实路径，识别项目子目录、仓库根、worktree、符号链接；记录用户范围，不能因发现 Git 根就扩大分析范围。无 Git 也可交接。
2. Git 可用时通过只读命令确认 `rev-parse --show-toplevel`、`branch --show-current`、`rev-parse HEAD`、`status --short`；必要时读取差异、相关 commit 和 `worktree list --porcelain`。设置 `GIT_OPTIONAL_LOCKS=0`，不 checkout、fetch、提交或清理。工作树状态不等于已发布版本。没有 HEAD 或处于 detached HEAD 时如实记录。
3. 先用 `rg --files` 或现有文件清单发现资料；仅按需补看隐藏或 ignored 的结果/上下文目录。不要读取 `.env`、凭据存储、整棵主目录；remote URL 若带认证信息只保留脱敏仓库标识。外部 CTX 等链接先确认与项目关系再读取，不遍历其他项目。
4. 资料截至时间是本次证据可覆盖的时间，分别记录当前快照时间、最新已读历史事件时间和各结果的发生时间；mtime 只是线索。旧结果的版本不能用当前 HEAD 填补。

## 按实际能力发现历史

逐项记录“可用并尝试/不可用/受范围限制未尝试”及结果；只调用环境实际暴露的接口。不要假造 CLI 参数、数据库字段或工具名。

| 渠道 | 实际检查与归属 | 覆盖边界 |
| --- | --- | --- |
| Codex 宿主任务接口 | 若实际提供项目列表、任务列表、归档列表、读任务/分页等工具，先读返回的 ID、项目、cwd、仓库和父子关系，再读取匹配任务 | 列表可能只含最近任务；必须记录限制、归档覆盖、cursor 和截断。界面摘要用于导航，不能冒充完整消息或工具结果 |
| 本地 Codex 记录 | 查看实际 `CODEX_HOME`；未设置时将 `~/.codex` 作为待核验位置。只检查目录和少量元数据字段，再扫描已发现的记录索引 | 某些版本使用 `sessions/`、`archived_sessions/`、`session_index.jsonl`；这只是候选，存在与格式每次核验。禁止读取认证文件或把索引标题当归属证据 |
| 用户提供的导出 | 检查项目路径/ID、仓库、会话时间、消息角色、工具调用及结果、分页/截断标记 | 无可靠元数据时标“归属待确认”；用户明确指定归属可作为依据但仍标记其来源。导出缺失附件不能当成附件不存在 |
| 当前可见会话 | 仅包含宿主实际提供的内容，按消息及时间定位 | 不能据此断言已读同项目所有历史；禁止调用或导出宿主私有恢复状态作为用户项目档案 |

本机创建时（2026-09-11）已确认有 Codex 桌面任务读取接口，且三个本地候选位置存在并可读；这仅是能力/路径检查，**没有以此测试读取所有真实项目会话**。运行本技能时仍须重新核验，不依赖创建机器。

若只能访问本地 JSONL，先用 JSON 解析少量记录确认形状：一些版本的 `session_meta.payload` 含 `id`、`cwd`、`git`，正文记录含角色、事件类型和时间；不要把这些候选字段硬编码为事实。索引缺少 cwd 时，用记录元数据补核归属。SQLite 如确需使用，仅在检查当前 schema 后以只读连接读取必要列，不修改数据库、不复制完整历史库。

**归属规则**：规范化路径相等/落在已授权项目范围，或可证实的同仓库 worktree/重命名关系，配合项目 ID、remote（脱敏）或 commit 等。路径前缀要按目录组件匹配，`/work/alpha` 不等于 `/work/alpha-other`。同仓库不同项目子树也可能无关。仅有相同关键词、任务标题、用户或模型不够。归属冲突的正文先隔离，不引入项目结论。子 Agent 用父任务关联继续确认，不能只按同时发生归并。

## 清单与逐一浏览

所有发现范围先入清单，可在取证笔记中维护，交付时合入来源索引：

| 来源 ID/类型 | 项目归属依据 | 定位/时间/版本 | 可访问状态 | 已读范围与深度 | 未读部分/原因/下一读取点 |
| --- | --- | --- | --- | --- | --- |

状态严格区分：已发现且已阅读、已发现但尚未阅读、无权限访问或无法解析、未发现且无法确认是否存在。混合情况拆行或写清已读页/行；浏览了元数据不表示正文已读。

- 按已发现的相关历史清单逐一浏览消息序列及工具事件，标记需求、转折和尝试；关键事件回读上下文、命令参数与对应结果。先浏览全可见范围，再选择深读，不能以关键词命中替代历史覆盖。
- 工具调用≠执行成功；配对调用与返回的 ID、时间、退出状态及结果。stdout 写着 passed 仍需辨认验证对象、断言和条件。超时、截断、只存摘要、结果附件缺失须明确。
- 去重按会话/消息/调用 ID、来源版本和事件关系；同一尝试在主 Agent、子 Agent 和总结中反复出现，不是三个独立证据。事实相同可合并，条件不同的成功/失败保留。
- 大材料分批推进，记录每条的游标/行区间/深读事件；若跨上下文恢复，保存必要的已脱敏证据笔记及下一读取点，不建立额外服务。分母未知写“已发现 N 条”，不能写“N 条即全部”。
- 因预算/长度未读完：交付部分覆盖，列出未读范围及受影响判断；不能偷偷只保留最新 N 次或声称完整。

## 缺失与失败

权限拒绝不通过换账号、修改权限、私有缓存或其他手段绕过。对暂时性工具错误可有限重试或使用已授权导出；仍不可用则保留错误类别、尝试渠道、范围和影响。格式不支持时尝试已有解析能力，失败记录具体文件/区间，不将解析失败转换为空记录集。

历史缺失仍输出资产侧可确认状态，并明确：“不知道此前选择此方案的完整理由，因为相关历史正文不可访问；可补充带项目标识和时间的会话导出、工具结果及相关版本。”只补缺口所需材料，不要求整个账号日志。未访问到历史不能证明未尝试；缺少测试报告不能证明从未测试。
