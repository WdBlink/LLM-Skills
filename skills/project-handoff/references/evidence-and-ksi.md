## KSI 机制在本技能中的执行位置

| KSI 的原机制与定位 | 本技能实际执行 | 交接中可检查的产物 |
| --- | --- | --- |
| Task-level forum：把一次轨迹变成有证据的局部主张；论文 §3.1 Stage 1 | 宿主取证保留观察和原主张；writer 绑定尝试、条件与来源 | 例如“运行 R1 超时”与“该方法不可用”分别保留，后者进入待审主张 |
| Cross-task forum：其他尝试对已有主张支持、反驳或综合；§3.1 Stage 2 | writer 在同项目不同尝试/版本/子任务中对照，说明可比性并修订；critic 独立回查证据 | 哪个反例使哪条主张收窄、拆分、撤回或保持未决；不能只有几条并列摘要 |
| Distillation：为后续任务选择可行动、有依据、有范围的结论；§3.1 Stage 3，附录 E.3；上述 `distillation/prompts.py` / `types.py` | planner将审议纳入中心问题和章节依赖，writer在相应论证中保留结论及边界，B状态在当前判断和下一步中独立说明；有缺陷才受限修订并再审 | 接收方知道何时能采用、什么已试过、哪些变体仍未知，来源不能只给路径 |

这里把跨任务对照缩为**同一授权项目内的跨尝试对照**，不收集其他项目资料，也不声称复现多 Agent 论坛的效果。讨论焦点决定哪些结论值得保留，但不能删掉理解项目必需的上下文。

2026-09-14 的编排改造复用此前已核验的 KSI 方法定位，没有本轮重读上游或复现实验。独立 writer/critic/reviser、冻结输入、受限 patch 与程序发布是本技能借鉴本机 workflow-skill-creator 中 ResearchStudio 方法的工程实现；critic 不是 KSI 跨任务论坛的复刻，稿件 review_token 只防旧评审误用，不证明知识真实。

六类内容（经验、约束、具体否定、陷阱、检查、下一步）是 KSI 的组织启发，不是六个必填栏目。没有观察或相反来源时如实写缺口；不能为了生成“共识”编造发言、反例、因果或验证。

不迁移论坛服务、多代运行、任务族、生成下一轮 Agent、固定置信度阈值、固定条目/字数上限、领域词汇表或运行数据库。上游提示词中的“两个参数化失败”等数量门槛**不能**成为否定整个方向的充分依据。本技能要求结论范围始终不超过证据。

## 怎样从主张对照得到交接结论

对重要主张按以下字段组织紧凑证据链，直接写进最终文件即可：原主张及来源 → 支持/反驳/限定的尝试与条件 → 判断变化及理由 → 保留的结论和边界。只记录真正影响项目的主张，不为每个句子编号。

证据有不同条件时，先判断这些差别是否限制比较；不能将“不同配置的相反结果”直接判成有人说谎。一个反例可以推翻“所有条件都成立”的说法，却不自动证明与它相反的普遍说法。结果只展示参数同时变化时，不能未经对照把改善归因于其中单个参数。

以下是说明方法的合成例，不是上游实验：

| 原主张 | 对照证据 | 修订与处置 |
| --- | --- | --- |
| T1 在参数 p1 失败后声称“方法 M 无效” | T2 在 p2、条件 C 下成功；T3 在 p2、条件 D 下失败 | 撤回整个方法无效的结论；保留 p1 的实际失败，以及 p2 在 C/D 下各自的结果；未试的 p3 仍未知，不能凭此推荐其已可用 |
| 同一次运行“无重复结果” | 另一审计记录说“有两个重复”，但两者口径未提供 | 保持未决，保留两条来源和口径缺口；不平均结果、不挑更新的记录当真 |

这类整理相对逐段摘要的区别在于**后面的证据实际改变了前面的主张**。若最终只是“第一次失败、第二次成功”而没有修订结论、条件和当前影响，就没有完成此步骤。

蒸馏后的 A 类知识仍不能替代 B 类状态。例如“在 C 下 p2 有支持”可以进入经验；“当前仍临时采用 p2、D 的验收未过、下一次检查待批准”必须独立进入当前状态。A/B 是本技能为交接增加的保留规则，不等同于 KSI 的 per-task/cross-task bundle 划分。

## 尝试、知识、状态三种记录

重要尝试可写成紧凑段落或表格，不要求额外 JSON：

- **尝试**：问题/背景；有记载的假设/目标；行动及版本、数据、配置；观察（含指标、单位、样本数、对照）；结论及来源；未排除解释；后续修复/替代；对现在的影响。
- **A 可复用知识**：结论；支持证据摘要及定位；适用条件；限制/反例；未验证变体。单次失败只限制该条件；成功只支持测过范围。证据不足以泛化就标“局部观察”，不硬凑经验。
- **B 本次交接状态**：当前有效方案/版本/配置；未提交差异；产物和证据对应关系；临时限制；未完成验证；既定计划和未决选择。B 单独保留，不经过“可泛化才保留”的过滤。

## 判断证据，而非排列来源权威

| 要回答的判断 | 对应证据与局限 |
| --- | --- |
| 目标、约束和验收 | 当前明确需求、有效契约及有时间的用户决策；代码只能反映实现，不能替用户改目标 |
| 功能是否存在 | 当前入口/调用链及实现；不能据存在推断可用性或已经部署 |
| 某操作是否执行 | 配对工具调用、输出和时间；命令文本或 Agent 自述不足 |
| 是否验证、结论能否推广 | 结果/断言、代码版本、数据划分、配置、环境和覆盖；单个 exit 0 或旧成功不足以证明当前全部正确 |
| 为什么转向、失败根因 | 当时明确理由、排查观察和可支持因果的对照；没有记录则未知或推断 |

对影响判断的结论，保留“结论类别 + 截至/条件 + 支持来源 + 相反来源/缺口”。`已验证事实` 可来自已核对的历史结果，但必须写清“记录验证”或“本次验证”；如果只存在一张无方法/来源的结果表，只能说明“该表记录了此数值”。

例（合成）：v1 在空输入抛错，v2 添加空输入分支，v2 的两项回归通过。可写“该失败在这两项回归条件下已修复，真实数据覆盖未知”；不能写“该方法失败所以放弃”，也不能写“v2 已彻底解决”。若 v3 改了分支而未重测，v2 通过仍是历史证据。

先按相同判断对象与条件比较；较新的文档可能抄旧结果，较旧的用户决策可能仍有效。区分“已读材料缺少支持”与“证据直接相互矛盾”：某一次评估取消，不能在历史不完整时排除另一次成功运行；没有绑定同一尝试的完成宣称应先标为待核源。冲突无法解释时明确双方、当前影响、需要的最小补证，不选一个便于讲故事的版本。
