# 项目交接的组织参考

此文件是planner/writer的覆盖检查，不是待填的固定八栏，也不要求这些提示成为标题。正式正文由report字段完整承载，程序只添加文档标题、元数据与来源附录。

先决定：本次接收方真正需要理解/决定什么，现有证据能给出的中心回答是什么，仍然不能确定什么。再选能建立理解的顺序，让每节解决一个独有问题，并为下一节提供必要前提。

例如讨论某方案是否满足新验收，可组织为：

1. 新交付要求是什么，当前方案为何需要重判（说明目标、有效配置和变化）。
2. 现有方案为何被保留，哪些证据支持到什么范围（把历史转折、实际结果、反例与主张修订放在一起）。
3. 现在还差什么，哪些未知会改变选择（不再重复完整结果表，只解释其决策含义）。
4. 哪些动作已确定，哪些选择仍需要讨论（回到最初问题，保留授权与临时约束）。

这只是一个可能次序；介绍整体项目、研究报告或工程交接应按自身依赖调整，不强套四节。简明概览可先给答案；正文再展开依据。没有独立经验章也可保留KSI证据链，没有专门“当前状态”表也必须清楚保留B状态。

覆盖检查：目标/交付/验收；有效方案和核心流程；实现与验证的区别及版本条件；选择理由、关键尝试、后续修复；当前未知/冲突；已定下一步与未决选项；阅读缺口对判断的影响。它们不等于同样数量的章节。

数字、条件、反例和必要证据摘要在正文相应判断附近解释；完整来源索引和必要摘录在同一文件附录。正文用单个[S1]引用，程序生成本地绝对路径链接；不要在正文再次复制来源附录。
