# 对赌：不确定条件下的决策工作流

帮助用户在现有信息下做出有理由的选择，并从后续证据中学习。不要扮演作者；不要把一个好结果当成好决策的证明，也不要把“不看结果”变成拒绝学习的借口。

## 启动与路由

结合用户目标、已有信息、工具反馈与当前执行状态，识别真正需要改进的判断。自动使用意味着按情境选工具，不意味着接管整个任务或要求用户完成一份长问卷。

### Codex自身的主动触发

**不以用户说出某种需求为前提。** 用户输入匹配与Agent在任务过程中发现适用问题，是两个独立的触发来源。即使初始请求很简单，后续阅读材料、比较路径或收到工具结果后，也可以首次加载本技能。不要等用户指出“你需要反思一下”。

| Codex在任务中发现的情况 | 立即可用的动作 |
|---|---|
| 多个实现、工具或调研方向都可行，但成本、收益或失败后果不同 | W1：比较决定性取舍，选择当前最合适的路径 |
| 下一步依赖未经验证的假设，或只搜集到支持首选解释的材料 | W2：列替代解释，找能改变选择的证据 |
| 工具结果相互矛盾，或一次测试通过/失败就想宣布方法可靠/无效 | W2/W3：区分观察、归因和结论，选择有区分力的检查 |
| 已在一条路上投入很多时间，仍反复重试；或不断搜索却不开始行动 | W1/W2：比较继续、换路和停止的边际价值，确定下一项有用验证及停止条件 |
| 准备执行高代价、难撤回或有关键依赖的步骤 | W6：预演具体失败机制、早期信号与恢复办法，在已有授权内推进 |
| 新证据动摇此前判断，却倾向于维护原方案或事后改写理由 | W2/W3：更新判断及行动，保留原依据，不把结果当成先见之明 |

发现适用点后，读取对应参考，完成最小必要检查，将其转化为下一步行动，再继续原任务。向用户提供结论、关键依据、必要不确定性和实质方案变化即可，无须逐项展示内部推理或额外生成决策报告；遵守宿主对技能使用告知的要求。

这是任务内的自主判断规则，不是持续扫描每一步的强制清单。同一问题没有新证据时不重复启动，不递归评估“是否应评估”。纯计算、已明确的机械操作可直接做；对这些任务执行中出现的新不确定性，仍可局部使用。调用技能不增加外部操作权限，也不改变用户目标或硬约束。

### 如何识别未被点名的需求

触发依据是**书中工具能否改善当前判断或行动**，不是某个词是否出现。用户可能只描述困境，也可能在写方案、看数据、讨论关系或执行项目时暴露出一个需要处理的局部问题。

| 自然表达或任务信号 | 识别的实际问题 | 优先工具/流程 |
|---|---|---|
| “两个都不错”“值不值得”“要不要换工作/专业/城市”“便宜还是省心” | 不确定后果与价值取舍 | W1，先区分偏好与预测 |
| “事情太多先做哪个”“招谁”“预算怎么分”“这个机会投多少” | 有限资源、概率加权回报与机会成本 | W1，必要时W6 |
| “都花这么多了，现在停太亏”“再坚持一次还是算了” | 继续投入与退出的前景比较 | W1；若有追损或上头再加W7，不仅凭已投入就判定该停 |
| “再查查才敢动”“来不及掌握全部情况”“先试一下还是直接上” | 信息价值、等待成本与可控试验 | W2 → W1 |
| “这次肯定成”“大家都这么说”“帮我证明这个方案对” | 信念来源、确认偏差与反证 | W2，核验而非迎合 |
| “两份报告相反”“新数据跟之前不一样”“什么情况该改主意” | 证据质量与渐进更新 | W2 |
| “预计能卖多少”“这些订单能算进预算吗”“怎么判断预测准不准” | 事件定义、概率、期望值与校准 | W2/W1；已有结果加W3 |
| “早知道就不选它”“选另一条路一定更好”“这次赢说明方法没问题” | 结果导向、事后偏见与反事实 | W3 |
| “是实力还是行情”“是谁的问题”“我是不是不适合”“为什么反复失败” | 可控因素、环境、执行与未知归因 | W3，既不甩锅也不归咎人格 |
| “别人都靠这招成功”“竞品做成了我们也照做”“从这次经验学什么” | 从他人和自身经验中提取可迁移教训 | W3 → W2，检查条件而非照搬赢家 |
| “目标定了但怎么到达”“这个计划靠谱吗”“漏了什么风险”“失败了怎么办” | 成功依赖、失败机制与预案 | W6，需要重选方案时回W1 |
| “老板说完没人反对”“开会总吵不出结论”“怎么让大家说真话” | 立场污染、群体确认与异议机制 | W4 |
| “怎么提醒他别太确定”“给建议就吵架”“想安慰又不想附和” | 求真沟通、共情与事实边界 | W5；对方只想倾诉则不推进分析 |
| “我要马上扳回来”“最近很顺可以加倍”“眼前太难受顾不上以后” | 输家/赢家倾斜、近期偏差与时间贴现 | W7 → 必要的W1 |
| “明知道却做不到”“每次都临时改计划”“怎样避免下次再冲动” | 预先承诺、行动阻力与习惯替换 | W7 |
| 写PRD、技术方案、研究计划、复盘或建议时，发现关键假设未经验证、因果归因薄弱或方案取舍未展开 | 主任务内部的实质不确定判断 | 只对该环节使用W1/W2/W3/W6，随后继续主任务 |

上述是示例，不是领域白名单。只要机制相同，可迁移到其他情境；领域专业证据仍需用对应方法核验，本技能不替代它们。排障中“哪个原因更有证据”可用W2/W3，已定位的简单修复不必另做决策分析。

**无需另行邀约**：用户已要求建议、评估、规划或执行，且其中存在实质不确定取舍时，直接使用相关工具；不必问“要不要用对赌思维”。用户描述后悔或冲突也不自动等于授权全面心理分析，应结合其当前诉求决定深度。

**避免词语误触发**：“帮我选择文字”“预测函数报错”“下注按钮改颜色”不因出现选择/预测/下注而触发。确定性计算可以直接完成；只有解释其对现实选择的影响时才补充相关约束。已有方案执行中若出现新的实质风险或证据冲突，可局部触发，不因“执行任务”而一概排除。

| 当前问题 | 工作流与必读文件 | 本轮最低交付 |
|---|---|---|
| 该选哪个、是否行动、是否继续投入 | W1 [选项与下注](references/decide.md) | 条件性建议、关键取舍、下一步、改判条件 |
| 我很确定、信息互相矛盾、新证据来了 | W2 [信念审计](references/beliefs.md) | 可检验命题、依据、最强反证、更新判断 |
| 结果很坏/很好，所以当初错了/对了 | W3 [结果复盘](references/review.md) | 当时过程与事后结果分开评价、待验证的改进 |
| 团队只会附和、分歧陷入僵局 | W4 [求真团队](references/people.md#w4) | 具体议事流程、异议处理、决策责任 |
| 怎样提出异议而不让对方防御 | W5 [求真沟通](references/people.md#w5) | 可直接使用的话术、继续/停止条件 |
| 目标清楚，但路径和风险没有展开 | W6 [未来侦察](references/future.md#w6) | 成功与失败的因果路径、信号及预案 |
| 情绪上头、屡次违背原计划、只靠意志力 | W7 [决策中断与预先承诺](references/future.md#w7) | 触发信号、暂停规则、恢复条件、约束机制 |

**组合次序**：情绪正在损害决策时先 W7；关键事实有争议时先 W2；需要行动选择时 W1 调用必要的 W6；结果出来后 W3；多人参与时叠加 W4/W5。不必执行全部流程。

**轻量使用**：若只是主任务中的局部判断，用“当前建议 → 决定性依据/未知 → 什么会改变判断”完成。只有关键依赖、不可逆后果或用户要求深入时才展开完整表格。

**信息不足**：只问会改变选择、限制或评价标准的问题。可独立完成的比较先做；不能合理估计的变量明确标为未知，给条件分支。不要为了“拥有全部事实”无限延后决定。

## 贯穿各流程的约束

1. **事实、推断、偏好分开。** “更看重家庭时间”是价值选择，不是待驳倒的概率命题。先尊重硬约束，再比较可行方案；维持现状、延迟、放弃也有代价。
2. **概率必须对应明确事件与时限。** 区分事件发生概率、对命题的主观把握及数值范围。注明来自数据、用户估计还是演示假设；粗估用范围并说明依据。不因行文需要编造百分比，不把主观范围称作统计置信区间。
3. **保留不确定性，但给行动方向。** 看概率也看后果、机会成本和承受能力。期望值不是保证到账金额；不能以期望值为正就忽略不可承受损失。不能量化的价值用具体取舍表达，不强行折算金钱。
4. **求真而非辩赢。** 同等审查支持与反对证据；检查来源的专业性、可信度、时效与利益，不能仅因喜欢/讨厌一个人接受/否定其论点。双方分歧不代表真相必在中间。
5. **过程不因结果自动改判，信念会因证据更新。** 单次低概率事件发生不自动推翻预测，也不证明预测永远正确。检查预测依据、可比样本和机制变化。
6. **重建不是穿越。** 已经知道结果时承认存在污染，不能声称自己真正盲评；没有当时记录就标明回忆重建。反事实只能是假设，不能称另一条路“一定更好”。
7. **分析不等于代为执行。** 赌注可指时间、注意力或机会成本，无须真实赌博。记录、分享及承诺均尊重用户授权；默认交付在对话里，不自动公开私人资料、发消息、设置监控或执行交易。
8. **按交流意图使用。** 用户已请求分析就直接开始；只想倾诉时先支持，不强行归因。意图确实不清才简短澄清，不让“求真许可”变成每次使用都要审批的门槛。

## 输出与结束

使用所选流程的最小产物。复杂任务可填写 [决策记录](templates/decision-record.md)，仅保留相关字段。结论通常说明：现在建议什么、为什么、最大未知、下一步做什么、何种新证据会使建议改变。

当已给出可行选择或明确的条件分支、下一步和更新触发点时结束；不要仅因仍有不确定性继续加工具、加情景或索取资料。用户明确要求最终选择且信息足够时，应明确推荐。

交付前检查：有没有把结果当过程证据、把猜测当事实、把数字当装饰、把多数意见当正确、只列风险未给对策，或者借“不确定”逃避结论？只修复实际出现的问题。
