# Benchmark 设计案例

这些都是本地构造的教学例子，不是论文原案例、真实实验结果或已通过验证的任务。用于练习不同领域的契约与判定；迁移时替换成项目的实际资料。不要把示例容差、运行次数或数据规模照搬成统一标准。

## 库存汇总

**真实工作目标：** 仓库人员需要从事件记录恢复每个商品的库存，发现会影响补货的缺失或重复处理。

候选题面：
> 输入为 UTF-8 JSON 事件列表。每条记录含 event_id、sku、整数 delta；同一 event_id 的完全相同重传只计一次，同一 event_id 的冲突记录须报错并停止。按 sku 汇总净变化，输出每个出现过的 sku 及整数 total；顺序不限。使用提供的离线文件，在声明资源内完成。

这些是假定业务规则，不是要求所有库存任务使用相同约定。实际设计还应补清负库存、空输入和错误输出接口等会影响验收的条件。

**坏评分：** 与参考答案文本逐字相等，或检查候选程序是否用了 SQL、特定变量名；模型结果正确却仅因行序不同失败。

**改法：** 按 sku 建映射核对整数及覆盖集合；拒绝重复输出键、漏项、伪造总数和未处理冲突。允许 SQL 聚合与流式字典两个合法实现。只在业务约定排序或接口必须固定时检查相应格式。

**反例测试：** 全部数字不变但交换 sku 归属；重复事件计两次；零总数商品被漏掉；空文件直接成功；只复制公开样例答案。对每种变体事先确定预期，不能见分数后改规则。

**难度判断：** 小样例只检查语义，不证明任务难。若目标是大规模去重与冲突恢复，应从真实负载和处理约束建立难点；不能靠隐藏重传规则压低通过率。

## 故障定位

**目标：** 根据服务日志和配置恢复离线索引服务，接口通过健康检查且查询结果正确。

**问题：** 参考脚本直接把作者已知的配置行改成某个值；被测系统既看不到错误日志，也没有权威配置说明。参考脚本成功只证明作者持有答案。

**改法：** 提供同一组诊断入口、日志、配置及正常行为说明，让参考路径先定位原因再修复。隐藏真值只给评分器。验证修复后的行为及数据保持，不强制要求候选执行与作者相同的命令。

**反例：** 如果契约明确要求“不重启服务”和“保留现有记录”，直接重建数据库虽能通过健康检查也应失败；这是真实业务约束，应写进题面。多种正确修复都应通过，缓存过期造成的暂时恢复不应冒充持久修复。

**待验内容：** 从干净状态重放参考解和另一合法修复；检查被测权限能读到必要信息、不能读取隐藏答案；按业务实际需要检查重启后状态。

## 研究简报

**目标：** 从固定资料包生成一页供采购决策使用的比较简报。

**坏设计：** 仅让另一个 LLM 给“专业、好读、有洞察力”打总分，并称它是事实正确率。

**改法：** 把可核验的底线与偏好分开。底线可以包括引用映射到资料包、价格/条件与来源一致、字数范围、关键选项覆盖；对可读性和取舍帮助另用目标读者盲评、锚定样例与分歧记录。不给引用不存在但文风漂亮的简报以“事实通过”。

**边界：** 关键词存在不证明引用支持主张；程序无法覆盖的内容正确性保留人工核验或未验证状态。模型评委可以辅助找问题，但没有人工校准时不能宣称客观可靠。该任务属于混合评价，是本地扩展，不声称完全符合原文的纯程序验证场景。

**合法差异：** 不同结构或表达只要准确满足用途，应允许；如果表格列名是下游导入接口，则它是必要格式，不能按文风偏好忽略。

## 时延与协调

**虚假加难：** 模型在原预算内完成任务后，作者临时把时限减半；或者加入十项不相关小产物，让整题更容易漏项，却继续声称测量算法推理。

**有依据的约束：** 若部署规格要求单请求 p95 时延不超过明确门槛，保留该限制，并固定硬件、并发、预热、样本量、测量口径与随机噪声处理。参考解也须满足。限时不是天然不公平；事后为制造失败调限时才改变了测量目的。

**协调例外：** 若目标本来是跨系统交付，多个相互依赖的产物可以构成同一真实任务；检查最终一致状态，并用分阶段日志定位协调失误。不能把多个无关小题相加就称长程能力。

**诊断：** 分开记录算法错误、资源超限和基准机不满足声明条件。降低测试负载后通过是定位线索，不自动推翻真实 SLA。

## 评分隔离

**环境漏洞：** 候选可写最终评分文件，或者提交成功标记就能跳过实际检查。

**改法：** 评分进程与候选执行权限分离；由评测方重新计算结果，保留候选可写范围和不可见真值清单。输出目录可以写，测试与评分逻辑不能被候选替换。

**验证：** 在隔离环境尝试伪造成功标记、篡改可见测试、复用上次输出；都不能替代真实任务完成。修复后运行正常解确认仍能产生合法输出。若某个共享挂载方式影响整套任务，应修 harness 并回归相关任务，而非只屏蔽某条攻击字符串。

**边界：** 有审计日志不等于无漏洞，没观察到攻击也不等于无法作弊。攻击范围只限已授权的测试环境。

## 图像分类

**目标：** 比较两个训练流程在新采集批次上的识别效果。

**坏设计：** 将相邻视频帧随机拆分到训练与测试，只报每个流程最佳 seed 的总准确率；把来源重复帧当成独立泛化证据。

**改法：** 按实际应用的独立单位划分采集批次或设备，明确目标是已见条件还是新条件；冻结开发/评价划分。记录训练预算和重复方案，报告每次结果、分组性能与适用区间；比较条件不同时写清差异，不给未经支持的单一排名。

**评分器反例：** 类别 ID 映射交换、缺失预测被悄悄移出分母、只挑易样本评分、从答案文件读标签。验证器自身的可重复性与训练算法的随机性分开检查。

**边界：** 如果业务只关心同一设备的未来帧，不强制改成跨设备 benchmark；按时间等实际泄漏路径设计。样本过少时交付描述性结果及缺口，不用复杂统计包装成确定结论。
