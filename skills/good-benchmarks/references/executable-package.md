# 可执行交付与复测

目标是让另一个人或 Agent 拿到产物后按同一规则复测，不需要重写裁判。按 [场景选型](benchmark-forms.md) 确定任务和成功依据，再沿用项目目录、数据格式、测试工具和发布登记；下面是产物责任，不要求固定文件名或搭建平台。

## 最小产物与证据

| 责任 | 实际落盘内容 |
|---|---|
| 数据 | 可使用的任务说明和初态/输入，或版本化获取/构建入口；记录来源、授权、真实/合成性质、数据角色、样本单位、切分和曝光。预处理文件需要实际文件或可重建的准备流程，仅有原始研究链接与哈希不够 |
| 规则 | 任务契约和语义参数配置，包括单位、阈值、seed、失败分母、重试与聚合。影响排名的选择在看结果前冻结 |
| 执行 | 保存领域评分器、被测调用/输出导入入口、依赖及可复跑命令。数据处理和计算调用脚本；模型只处理确需判断的部分，不每次生成同一算法 |
| 校准 | 参考路径和产物；独立核对的正例、合法替代、错误与边界样例及预期判定。预期不能由待测评分器自动生成后自证 |
| 证据 | 实际命令、版本绑定、返回码、输出和诊断、资源用量、已验证范围与缺口。日志可另存，但须关联被冻结输入与规则 |

逐指标记录评价单位、数据版本、原始判定来源、代码入口/参数、独立预期、输出字段和聚合口径；多个指标可共享模块。程序直接算的部分与读取模型/人工标签后汇总的部分分开说明，不让固定公式掩盖语义裁判依赖。

## 按形态补齐交付

| 所选形态 | 相应产物与最小复跑 |
|---|---|
| 静态记录 | 样本 ID/附件、评分侧标签/等价规则、划分清单、保存的匹配入口；对合法等价与语义错误复跑 |
| 可执行任务包 | 题面、输入/仓库版本及绑定、环境/依赖、预算、输出契约、评分入口、参考路径与正反例；从干净初态执行并核对目标行为及回归 |
| 交互环境 | 环境或任务服务、初态与 seed、动作/停止协议、状态或动作验收器；验证真实转移、目标与保留条件、跨运行重置 |
| 生成式任务 | 生成器/采样配置、来源与版本、seed、实际实例清单、可解与评分检查；保留同分布比较和模板/实体隔离证据 |
| 冻结运行评审 | 源记录及证据身份、快照、纳入/选路/去重规则、确切评审包、rubric/评审配置、原始判定、缓存与汇总入口；重建报告与重新调用裁判的稳定性分别记录 |
| 现场/前瞻任务 | 可重放部分、实际任务与配对条件、服务/硬件状态、时间、故障、资源及后续结果记录；只报告实际可重建/已观察的范围 |

这些产物可组合，采用已有实现就不再新建同功能脚本。文件不能公开时登记受控位置、授权和取得方法；完整公开交付与私有受控复现分开报告，不能把数据未公开说成数据不存在。

评分器及其答案不挂载给应盲测的求解器。不能随包分发的数据/答案也不要复制进报告；记录受控路径或授权获取方式。公开样例不能充当独立评价集。

真实数据缺失不妨碍把能确定的解析、评分公式和检查先实现；合成数据必须明确标识。复杂环境/人工流程可先固定可回放部分；未实现的关键链路仍是缺口，不能把几条公式断言称为端到端 benchmark。

主观任务保留 rubric、锚定样例、评审记录与分歧处理，程序仅检查可判定部分。明确只需讨论的请求可以只交设计；报告清楚为何没有可执行包。不得为满足形式要求伪造数据、预期或执行日志。

## 冻结、运行、复用

1. 检查已有产物并复用；补齐必要输入、领域脚本和校准样例。先确定预期再测评分器。
2. 冻结契约、配置、数据/构建入口、依赖锁定信息、评分器、参考路径与校准样例；按现有版本登记哈希。大型或受限数据用数据清单及项目已有快照验证器。
3. 实际运行参考路径和正反例，保存绑定此版本的结果。状态至少区分：文件完整性、工程回归/裁判 fixture、真实任务可解、裁判语义校准、比较/泛化证据、专家审阅。没做的项为 `not_run`，失败为 `fail`；fake judge 的端到端通过只能记为工程验证。
4. 复测先检查登记，再执行 README 中的同一入口及显式配置。不要根据 prose 重新写评分器，不只读取一份历史 `passed` 报告。新结果写到独立运行目录，避免覆盖冻结输入。
5. 检查失败先定位缺文件、数据/代码漂移或执行错误。语义改动建新版本并回归正反例与受影响基线；旧结果保留原版本，禁止直接重算哈希把变更伪装为原裁判。

在报告中分别写“合成样例端到端运行已通过”和“真实数据未运行”是有效部分交付。不能由前者推断数据代表性、难度、独立时期收益或真实业务效用。

## 可选的文件完整性入口

优先调用项目已有验证器。缺少时，可用本技能的标准库脚本（Python 3.9+）读取已有登记格式：

```sh
python3 /absolute/path/to/good-benchmarks/scripts/verify_artifacts.py /absolute/path/to/benchmark/registration.json
```

默认以登记文件所在目录为产物根目录；登记与产物分离时传 `--root /absolute/path/to/benchmark`。不依赖当前工作目录，不修改任何文件，不执行登记内的命令。

最小登记字段：非空字符串 `benchmark_id`、`version` 或 `design_version`（若同时存在须相同），以及非空对象 `sha256`（产物相对路径 → 64 位小写 SHA-256）。其它项目字段保留且不解释。路径须在根目录内；绝对路径、`..`、反斜杠、逃逸的符号链接和重复 JSON 键均拒绝。

返回码 `0` 仅表示**已登记文件**匹配，JSON 包含 `status: artifacts_verified` 和 `benchmark_validation: not_assessed`；`declared_status` 只是原登记的自述。返回码 `1` 表示读取、格式或文件匹配失败，给出具体错误；命令参数错误返回 `2`。

此入口不证明清单完整、来源真实、答案正确、执行曾发生、权限隔离或 benchmark 有效。空文件可能是边界样例；其哈希通过也不代表有数据。须用真实运行和独立核验补齐相关证据；只有这个入口通过时，不得升级原 benchmark 的验证状态。
