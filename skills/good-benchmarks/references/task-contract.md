# 任务契约与验证矩阵

以下是本地实施约定，不是论文发布的官方格式。使用项目已有格式承载这些信息；小任务可放在一个文件中，不为表格建立额外数据库。被测系统只接收解题需要的信息，评测者保留的审计表不应全部塞进题面。

## 最小契约

| 字段 | 应填内容 |
|---|---|
| 目标与用途 | 谁会用结果做什么决定；目标能力如何对应可观察行为、任务与指标；描述固定集合还是推断目标总体，后者的选样与外推依据 |
| 现有方案与复用决策 | 按 [检索与复用](reuse-existing.md) 保存候选及来源版本、实际获取/检查、逐需求覆盖和缺口；选择原样复用、适配、组合或新建的依据，保留组件、必要改动及对原版可比性的影响 |
| 形态与评价单位 | 静态记录、任务包、环境、生成器、冻结运行或现场协议的选用理由；一个样本/得分对应答案、产物、状态、动作、运行还是贡献，见 [场景选型](benchmark-forms.md) |
| 任务边界 | 一个任务的起点、结束状态、允许的输入族、未覆盖范围 |
| 输入与权限 | 文件/接口、数据版本、可见信息、网络/工具、可写范围；答案与评分状态的隔离方式 |
| 输出语义 | 需要交付什么、如何被下游使用；必要格式、单位、容差和无效输入处理 |
| 成功依据 | 答案/等价类、行为测试、目标与保留状态、参考动作、统计判据或 rubric；原始标签的代码/人工/模型来源，及它们各自支持的结论 |
| 合法变化 | 实现、语言、库、顺序、数值等允许变化；如果某项被禁止，写出业务或反作弊理由 |
| 资源与重置 | 时间、内存、计算、调用次数、依赖、随机性、清理与从同一初态重启的方法 |
| 能力难点 | 预计需要的诊断/推理/设计/协调；哪些失败不属于此能力 |
| 验证与评分 | 逐项结果判定、必要门槛、部分分的含义、故障分类、分母、聚合、重试 |
| 完成门槛与返工 | 按 [结果验收](result-acceptance.md) 冻结 A1 数据实例与数量/角色、A2 真实执行入口、A3 逐单位/指标得分与聚合、A4 相关现有方法及主要方法对/区分标准；事先声明用途、理由、重复/不确定性和未达标后的责任步骤，不用总分或历史通过替代逐项满足 |
| 可解证据 | 同信息参考路径、权限、版本与资源；未运行时给出论证及缺口。仅评审记录时分别登记证据包处理、参考判断和原任务执行状态，不把可评分当成科研问题已解决 |
| 比较参照 | 按用途选择参照及其信息/资源条件：参考路径证明可解，简单或针对性弱对照诊断捷径，代表性方法支持实际比较；不要求凑齐所有类型。构建验收须取得至少两个相关现有方法的区分实测，裁判正反例不能替代；未运行保留缺口。作者成功不自动代表专家人群表现 |
| 审阅与状态 | 实际审阅、版本、当前通过/失败/未运行项目及下一步 |
| 可复用产物 | 数据或获取入口、性质（真实/合成/样例）、切分与曝光；评分/运行入口、配置、依赖、参考产物和预期判定；路径、版本/哈希及复跑命令，见 [可执行交付](executable-package.md) |
| 数据角色与切分 | 被测任务、裁判正反例、裁判校准材料和工程测试分别登记；底层训练/测试、Agent 调优/评价和裁判开发/校准的划分不混用 |

给每项必须满足的结果分配 `R1`、`R2` 等本地 ID，建立下面的映射。ID 是索引，不是要求被测输出复述的标签。

| 要求 ID | 题面或领域依据 | 结果检查 | 合法替代 | 错误变体 | 证据 |
|---|---|---|---|---|---|
| 例：R1 | 汇总须含所有有效记录 | 按标识符和数值比较 | 行顺序不同 | 漏一条有效记录 | 测试位置与运行结果 |

检查有要求依据、要求有检查依据。未写明且无可靠领域惯例支撑的行为不能成为隐藏扣分项；安全、权限及真实接口要求不得因“多解公平”被省略。多个专家可能给不同正确答案时，说明等价关系，或澄清会改变结果的约定。

多指标还要关联评价单位、输入样本与版本、原始判定依据、运行/评分入口、独立预期、输出字段、分母和实际证据。复用现有配置即可，不要求一个指标一个脚本。需求覆盖表说明“为什么检查”，指标映射说明“实际怎样算、凭什么能复算”；二者不能由一份未执行的评分说明替代。

指标涉及弃答、拒绝、中止或不行动时，按目标区分任务产出、决策正确性及适用的安全结果；相应准确率/错误率须同时给出回答或执行覆盖率、分母及缺失语义。零错误不等于完成目标，任务未完成也不自动等于决策错误。若宣称中止正确，须核验触发条件、当时可得信息与任务是否仍可行，区分外部必要中止、方法自致不可行和未经尝试便退出。按契约保留原分数，不为改善解释事后改分。

## 验证矩阵

先明确预期，再运行候选评分器。不要把其输出反过来当真值。

| 输入评分器的样例 | 主要捕获的问题 |
|---|---|
| 经核对的参考产物 | 基本路径与预期真值不一致 |
| 独立构造的合法替代 | 绑定实现、顺序、展示风格或单一答案 |
| 只违反一项要求的变体 | 漏检、错误归因、部分分掩盖核心失败 |
| 字段完整、解释自洽但核心数值/行为错误 | 只查格式、相信候选自报指标；应独立核验的计算关系或目标状态未被检查 |
| 空白、缺字段、重复、非法值、边界尺寸 | 脆弱解析或默认通过；只选择当前接口实际相关项 |
| 超范围容差、单位改变、分母改变 | 数值看似接近但语义错误 |
| 涉及选择性回答或行动时：全弃答、无必要的提前结束与符合条件的中止 | 把零覆盖记成零误差、仅凭安全终态认定中止正确，或将合理中止误归为能力失败 |
| 复制示例答案或只迎合公开样例 | 只记住样例而未完成目标能力 |
| 可见答案泄漏、可写评分状态等受控绕过 | 得分与真实完成脱离 |
| 同一产物重复评分、同一初态重复运行 | 非确定性判分、残留状态、超时与环境噪声 |
| 合法等义改写/顺序变化与关键内容删除 | 无关表达影响判断，或语义缺陷未影响相应评分；前提是变换确实保持/破坏了声明属性 |

对多个合法方法，可使用性质检查、等价关系或独立计算核验，而非精确字符串匹配。数据容错不等于接受错误字段：哪些差异无关、哪些会改变结果由契约决定。

把 `solution_failed`、`verifier_error`、`environment_error`、`timeout` 等原因分开记录。无法区分时记未知并调查，不从一次异常推出能力结论。重复次数按评分成本与风险预先记录；廉价确定性评分器可做数百次稳定性检查，昂贵试跑可分批分析。少量烟测只支持所覆盖场景，不能证明零误差或全平台稳定。

## 试跑与难点归因

至少保留：任务、实例与运行的稳定标识及适用的配对关联；任务/评分器/环境版本，系统与配置，初态或 seed，预算，完整产物，评分明细，耗时/成本，失败位置。沿用项目标识，不要求另造字段体系。

这些记录应绑定实际执行的数据和规则版本。复测先核对版本，再调用保存的入口；哈希不一致时查明变更并建立新版本或恢复已冻结副本，不静默更新哈希以延续旧成绩。评分算法的权威实现只有一份；文档解释语义，配置存放允许变化的参数，发生矛盾时先修契约与实现的一致性，不由执行者临场选择口径。

试跑前核对任务内容与来源元数据；有结果后，结合常见/边界条件、易/难样本、系统分歧与疑似重复做针对性审阅，记录选择依据与发现。诊断性挑选不能用于估计总体缺陷率。

遇到一致性失败，建立一个待检验解释并做最小对照：

- 必要字段或约定不清：补清后单独试跑；若性能骤变，重新解释原先测到的能力。
- 怀疑方法选择困难：提供方法提示做诊断，但保持正式无提示版本及其成绩独立。
- 怀疑误判：从失败轨迹重建产物，按要求逐项人工核对，再交评分器。
- 怀疑资源或依赖：记录同一解在满足声明资源的环境下是否稳定；不事后放宽到只照顾某一模型。

诊断对照的结果只支持被控制的条件。应修任务/环境/评分器时先修正再重新冻结，区分纠错、覆盖变化、难度筛选和裁判变化；多项同时改动不能把全部分差归给其中一项，不将旧版与新版成绩混排。

## 跨领域的本地适配

### 统计与随机任务

定义估计量、独立抽样单位及适用层次，如任务家族、场景实例、训练运行、求解重复和重复评分；明确不确定性针对任务抽样、训练/求解随机性、评分噪声还是环境漂移。训练 seed、同场景多次运行和同产物重评分不能互换为独立任务数。需要泛化判断时保留与开发独立的数据，按实体、地点或时间等实际泄漏路径划分，不能只凭随机行划分声称独立。

区间或检验须匹配估计对象与依赖结构。独立二元结果可考虑 Wilson 或精确区间，不把正态近似作为小样本、零分或满分时的默认方法；相关或分层数据不能直接套独立样本公式。重采样不增加独立信息，区间也不修复选样偏差或错误裁判。固定集合的观察不因附上区间就自动获得总体解释；证据不足时交付描述性结果及缺口，不硬设统一 seed 数或显著性门槛。

在查看结果前确定主要比较、报告方式及对决策有意义的差异。可配对时保存逐项对应并分析差值，方法应保留配对与依赖结构；不以两个均值大小或区间是否重叠替代比较。统计显著不等于实际重要，未显著也不证明相等；不凭单次最高分排名。不要把“必须确定性”误解为禁止合理的随机算法。

### 主观或创作任务

拆开可程序检查的底线（例如引用存在、预算满足、文件可打开）和偏好/质量判断。为后者定义目标读者、评价维度、锚定样例、盲评与分歧处理；报告评审者与一致性。模型评委可作辅助，其校准须有独立人工材料。无法获得人工证据时交付方案或初步结果，不能声称达到原文的程序化客观验收标准。

### 实时、硬件或性能任务

若实时交互、硬件差异或时延就是目标能力，保留真实约束；记录测量环境与漂移，分开受控回放和现场评价。真实 SLA/内存上限可以是成功门槛，不因某模型接近通过才临时收紧。数据快照可解固定任务，但不能据此声称完成实时可靠性评测。

### 任务集合

先说明是最低能力验收、机制诊断、系统区分还是业务表现估计，可兼具用途但分别提供证据。覆盖范围与区分能力分开验收：回归任务高通过率可能符合用途；强系统排名遇到天花板时，先查未覆盖的真实能力和评分灵敏度，不以目标通过率调题。任务来源、纳入/排除与抽样单位须可追踪；若推断目标总体，说明实际样本与目标分布的关系。压力测试可富集罕见风险或困难条件，但其均分不能直接代表业务发生率；总体或选样依据不明时保留集合内描述。

避免重复或共享模板把相似任务当独立证据；对模型调优使用开发集，评价集版本及曝光情况单独记录。事前声明聚合权重和主要子组，并报告子组样本量：每题等权仍隐含类别频率权重，类别等权与业务加权回答不同问题，不编造未知的业务比例。事后切片标为探索性，不冒充预设比较。基线、资源和重试口径一致；若不同则披露比较的实际含义，系统整体与底层模型归因见 [场景选型](benchmark-forms.md#客观与稳定分别提供三类证据)。

### 专家审阅

结构/元数据检查与领域有效性审阅分别记录。争议的惯例需对应可查来源和版本；“业内都知道”不是证据。审阅意见需定位到要求、产物或轨迹，不以 AI 自评分驱动无限修改。缺少真人审阅不妨碍产出候选，但不能补造审阅者或宣称完成专家认证。
