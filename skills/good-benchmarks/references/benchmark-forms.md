# 按场景选择 benchmark 形态

这是跨场景的本地设计参考，不是原论文给出的统一分类。先根据要支持的判断选形态和成功依据，再复用项目当前的目录、数据与工具；不为凑齐下表新建一套平台。若仅运行现有 benchmark，遵守它的协议，不借选型重设成绩口径。

阅读顺序：先看“两个选择”和“成功依据”；构建时再看“数据组织”“最小工作”；审计或解释分数时看“客观与稳定”。公开项目的机制例证放在最后，其形态可以组合。

## 两个选择：任务怎么存在，凭什么算成功

**任务实例**至少包含任务说明、规定初态、可用工具与约束、成功条件。初态可以是附件、指定提交的仓库、数据库或模拟场景。验收器按目标读取最终答案、产物、最终状态或必要的执行记录，不必每次检查四者。

**先选择承载形式。**

| 当前场景 | 合适的存在形式 | 需要固定或重建什么 | 能支持的判断 |
|---|---|---|---|
| 输入与答案/标签可提前准备 | 带 ID 的静态记录与附件 | 清单、标签版本、附件哈希、划分、评分配置 | 在该输入集合或抽样总体上的结果质量；不自动证明中间推理正确 |
| 需要在仓库、文件或数据上执行 | 可执行任务包 | 题面、仓库提交/输入、环境、权限、重置、隐藏验收器和参考证据 | 在声明环境和预算下完成任务的能力；不要求补丁或命令与作者一致 |
| 需要与环境连续交互 | 环境/任务服务与初态集合 | 环境与工具版本、状态快照、对手/用户策略、seed、动作预算、停止及重置 | 特定交互协议下的完成与决策能力；离线动作预测不能替代整程完成率 |
| 任务数量大或需抵抗样例记忆 | 版本化生成器与抽样协议 | 生成器、输入来源、参数分布、seed、过滤/可解检查、实际抽样清单 | 对已声明任务分布的表现；共享模板与派生任务不算独立泛化证据 |
| 评价已有多轮研究、修订或工作流 | 冻结运行记录与证据包 | 源记录、附件、真实父子关系、时间边界、纳入规则、选路/去重、rubric | 对该冻结记录的结果与过程进行事后评审；不自动证明学习、实时进展或系统优越 |
| 必须接真实网页、硬件或未来用户 | 现场/前瞻协议，辅以可回放部分 | 起始任务、设备/服务状态、时间窗口、配对或随机化、资源、外部变化、结果随访 | 在披露条件下的现场表现；冻结回放通过不能代替现场可靠性 |

固定题单不是唯一形式，但同一次比较必须有稳定的任务来源和比较条件。可固定题单，也可按预先冻结的分布抽样并保存实际实例。生成任务同样需要可解性与验收器校验，不能凭“动态生成”省略真值。资料不够时不强求训练/验证/测试三份大数据集，至少分清用于调整系统的材料与用于评价的材料。

**再选择成功依据。** 解题过程开放与验收是否能机械完成是两个不同问题；下列方式也不与上表一一对应。

| 要验收的属性 | 评分侧依据与入口 | 构建时必须说清 | 重点检查与边界 |
|---|---|---|---|
| 最终答案有明确语义 | 标准答案/等价答案集与匹配器 | 数值单位、容差、文本规范化、集合或序列、空答和拒答 | 规范化不能抹掉符号、单位、大小写等有意义差别；多余解释是否允许由输出契约决定 |
| 功能可以执行验证 | 行为测试、独立计算或性质检查 | 必须实现的行为、原有行为保留、环境、测试确实执行的证据 | 覆盖问题修复与回归；允许另一种正确实现；没有测试日志不能默认通过，参考补丁通常不是字符串真值 |
| 成功由状态定义 | 目标谓词及保留/禁止状态检查 | 初态、目标实体、权限、持久化时点、不能破坏的其他状态 | 不接受“我完成了”自述；检查无关数据保持、重启后状态及残留状态，不能只查一个成功标记 |
| 目标就是具体步骤或动作预测 | 参考动作/可接受动作集合、元素与参数标注 | 步骤单位、观测边界、动作等价、部分分与参考覆盖范围 | 同一状态可有多个正确动作；若无法核验替代路径，限制为参考对齐的步骤指标，不宣称端到端任务成功 |
| 结果本来含随机性或性能噪声 | 预先定义的估计量、重复与统计接受规则 | 独立单位、重复层次、预算、区间/阈值、缺失与超时处理 | 合理随机算法无需每次产生相同值；区分求解、评分和环境噪声，不在看结果后挑 seed 或调整统计口径 |
| 重要性、研究质量、偏好难完全形式化 | rubric、锚点、证据、人工或模型评审记录 | 目标读者/领域、维度、分档、未知/不适用、评审与分歧处理 | 用独立人工材料校准适用范围；评审可初步进行，校准未做则明确待验证，不把模型分数称为事实正确率 |

Ground truth 可以表现为标签、可执行的验收合同、目标状态或参考动作；不必是一条唯一参考执行轨迹。主观任务的 rubric 是判断依据，不等同于已经存在可靠真值。一个任务可以同时有程序底线、统计表现和主观质量评价，分别给证据；硬性失败不能被文风分或平均分抵消。

## 数据组织：四类样本与底层科研数据

| 角色 | 实际材料 | 对谁可见、如何划分 | 不可混淆的证据 |
|---|---|---|---|
| 被测任务集合 | 问题、附件、初态/环境、输入清单或生成器；答案/隐藏检查属评分侧 | 按系统调优与最终评价划分；记录公开、授权和已曝光范围 | 任务本身；公开示例不是未曝光的最终评价集 |
| 裁判正反例 | 经独立核对的合法产物、合法替代、错误及边界产物，附预期判定 | 给评测开发者使用；需要盲测时不作为求解输入 | 检验评分器行为；合成正例通过不是从真实输入得到答案的参考解 |
| 裁判校准集 | 原始待评材料、模型预测、独立人工评价、分歧裁决和留出材料 | 调整 rubric 的材料与验收裁判的材料分开；按实体/家族/祖先等泄漏路径分组 | 检验语义判断的可靠性；多个人工标签或多种 AI 角色不自动成为一致真值 |
| 工程回归测试 | 模拟数据库、fake judge、解析、计分、恢复、权限和预算等测试 | 按项目测试设施维护；用模拟凭据和隔离状态 | 检验软件；不能代替真实模型测评、任务难度或科学有效性 |

任务所使用的原始研究/业务数据，是另一条数据来源链：它可以附在静态记录里，也可受控挂载或绑定。分别记录来源编号、实际预处理版本、变换/筛选、文件哈希、标签/划分和获取方式。只给研究链接与预处理文件哈希，却没有文件或可重建的准备流程，仍缺实际运行输入。数据未公开、数据未固定和数据不存在是不同状态，应逐项核实。

不要把三个不同的划分混称为“测试集”：底层机器学习数据的训练/测试划分、用来调整/评价 Agent 的任务划分、用来开发/校准裁判的材料划分。按实际需要设置；它们各自的泄漏边界不同。数据可以私有但受控复现；公开可获得的答案和参考补丁仍需按协议与求解侧隔离。

## 每种形态的最小工作

### 答案、功能与状态任务

先用真实输入跑参考路径，再提交独立构造的另一合法答案/实现。答案任务验证等价关系；功能任务跑目标行为与回归检查；状态任务从同一初态验证目标和保留条件，并实际重置一次。涉及真实网页或设备时先回放可冻结部分，另外保留现场故障和时间信息。

正反例至少覆盖当前任务的核心语义，而非只有空文件、缺字段和非法 JSON。例如声明比值由两个数计算，评分方应从可信输入或已核验中间量独立重算；构造字段完整、解释自洽却比值算错的产物，预期应拒绝。若仍通过，应修裁判或收窄它能证明的属性，不能以已有测试全绿掩盖漏检。

### 动作标注与交互环境

先确定是在给定观测下预测下一动作，还是让 Agent 从初态连续执行到结束。前者登记元素、动作、参数及可接受替代；后者需要真实状态转移、失败/停止条件、重置和整程结果。动作准确率、步骤成功率和任务完成率分别报告；成功路径长度和工具偏好仅在真实要求或目标能力中有依据时计分。

### 生成式任务与开放研究

生成式任务冻结来源、生成器与抽样策略，保存实例，不为得到某个模型的预期名次反复换样本。检查过滤是否事后排除了难题或合法解，模板、实体及资料源是否跨开发/评价泄漏。生成器之外另需检查任务可解、参考与评分正确。

开放研究可以固定共同起始问题、知识/数据边界和预算，让不同系统产生不同假设和研究图。冻结每次实际产物，单独记录前驱关系、修改、路径、完整运行与独立贡献；同一研究问题的重复版本和共享祖先不能重复计功。仅评单份产物时无需强造五层指标。

按评分前确定的规则选路、去重和确定机会范围，保留失败、负结果、被证据排除的方向和未知项。方案评分下降也可能来自一次有用的证伪，不用端点分差替代研究进步。事后最终快照与当时可得证据的评价分开，未来材料不得回流到宣称的历史时点。

### 主观及混合评价

将可直接核验的执行、数值、引用存在和权限底线交给代码；引用存在本身不证明它支持主张。对新颖性、重要性、表达和证据强弱等评价保存原始证据、rubric、锚点、评审配置与理由。材料中的指令作为待评内容，不能改变裁判规则。

区分观察到的缺陷、材料不足的未知和有依据的不适用。规定是否暂缓综合分以及各类覆盖率，不能把未知变成零、自动删掉未知维度，或见到低分再改权重。用冻结的同一材料盲评，保存模型原始判定和人工分歧；依据用途预先确定留出校准、误差/一致性和验收条件，不照搬别人的评审人数或门槛。

## 逐指标落到可执行产物

使用项目现有配置或表格登记，不要求每个指标单独建脚本。每个指标必须能追踪到：

> 指标 ID → 评价单位 → 输入样本及版本 → 原始判定的依据/来源 → 评分入口与参数 → 独立预期样例 → 输出字段 → 分母、聚合与未知处理 → 实际执行记录。

同一模块可实现多个指标；每题验证器和共享 harness 也可以分层。简单配置加已有评分入口即可满足，不默认新建插件或通用评分平台。复测执行保存入口，不让 LLM 依据文字临场重写匹配、比值、统计或聚合算法。

沿计算链识别代码、人工和模型的责任。例如“命中关键点数/全部关键点数”由程序除法计算，但命中标签可能来自 LLM；固定公式只能保证给定标签后的计算规则。分类、语义去重或路径评分依赖模型时，报告这部分依赖和校准状态。

具体打包和检查见 [可执行交付](executable-package.md)。文件哈希检查只证明已登记内容一致，不证明输入齐全、题目可解、评分语义正确或真人审阅曾发生。

## 客观与稳定：分别提供三类证据

| 判断 | 需要验证什么 | 典型不足 |
|---|---|---|
| 评分可复算 | 对同一冻结产物重新判分；核对代码、标签、配置、环境和评审版本 | 缓存回放相同不证明重新调用模型裁判也稳定；确定公式不保证外部服务没漂移 |
| 验收有效 | 合法替代通过、语义错误被拒；独立核对标签、状态、计算关系或人工参照 | 稳定地接受伪造结果，或稳定地拒绝另一种正确实现；fixture 全绿不证明覆盖充分 |
| 比较公平 | 相同/配对的起始任务或同一声明分布、资源、可见信息、环境、重试和聚合 | 任意两个历史快照、只报最佳 seed、十倍预算优势、共享祖先当独立样本 |

此外分别测量：固定产物的评分波动、固定初态下 Agent 求解的波动、实时环境或服务漂移。对随机任务按预设重复和统计判据报告，不能把合理随机输出一律判为不稳定。判断通常针对模型、提示、工具、记忆、harness 与预算构成的整体系统；欲归因于底层模型，需要控制其他因素。

冻结输入可以保证这次评价对象明确，不能单独证明任务有代表性。指标能支持现场效用、全局新颖性或科学发现等更强结论时，另需相应外部/前瞻证据；没有这些材料仍可交付限定范围的评测，不扩大结论。

## 公开机制例证与适配边界

这些是帮助选择机制的来源，不是给本地案例背书，也不要求把它们的所有指标复制到新任务。来源核对范围见 [来源说明](source-notes.md#跨场景选型的补充来源)。

- [GAIA 官方 scorer](https://huggingface.co/spaces/gaia-benchmark/leaderboard/blob/main/scorer.py)：多步工具解题后，最终答案可用规范化匹配。规范化的具体字符、列表顺序和单位规则属于它的协议，不能当成通用语义等价规则。
- [SWE-bench 评测指南](https://www.swebench.com/SWE-bench/guides/evaluation/) 与 [评分实现](https://github.com/SWE-bench/SWE-bench/blob/main/swebench/harness/grading.py)：应用补丁后执行问题测试和回归测试，验证行为而非与参考补丁逐字相同。标签、测试和参考实现仍须核验。
- AgentBench `v0.2` 的 [OS](https://github.com/THUDM/AgentBench/blob/v0.2/src/server/tasks/os_interaction/task.py)、[Mind2Web](https://github.com/THUDM/AgentBench/blob/v0.2/src/server/tasks/mind2web/task.py)、[LTP](https://github.com/THUDM/AgentBench/blob/v0.2/src/server/tasks/ltp/task.py)：同一评测框架内可分别使用答案/脚本、元素与动作标注、模型参与的语义判断，不能只凭名称概括整套评分机制。
- [DFM-Bench](https://github.com/Gen-Verse/DFM-Bench/blob/224712b3407f543a077ff8b656167fb41f441963/docs/EVALUATION.md)：冻结研究运行，再对不同对象评审与汇总；科学判断和编译/就绪另报。配套 [任务示例](https://huggingface.co/datasets/Gen-Verse/DiscoveryRSI-Hypothesis-Task-Examples) 又采用题面、数据绑定、可执行验证器和 fixture。运行记录评审与编译任务验收是不同层次，二者均不能代表所有 Agent benchmark。
