# Workflow Skill Creator

交付另一个 Agent 能直接使用的 Skill：稳定操作调用现有工具或已保存脚本，任务差异用参数表达，必要的语义判断由当前宿主完成。先保留用户要的结果与质量，再减少每次运行时重复读源码、写代码和推演流程的工作。

用户只要求分析时交付分析；要求创建或重构时完成实际文件、运行验证和约定的安装。不要因名字含 workflow 就增加多 Agent 或框架。

## 入口与材料

先确认待创建或修改的 **Skill 名称和绝对路径**，再读受影响文件。用户给的参考 Skill、文章和示例代码不是默认修改目标。

读取现有入口、相关调用方、代表性输入与已有工具的真实接口。按下面流程工作，仅在需要时加载参考：

| 当前需要 | 读取或执行 |
| --- | --- |
| 确定抽取步骤、参数和状态 | [设计方法](references/design-method.md) |
| 重构已有工作流、已有脚本但仍慢或不稳定 | [执行边界审计](references/execution-boundary-audit.md) |
| 批准的计划与最终产物不符、阶段完成却漏交付 | [要求闭环审计](references/obligation-closure.md) |
| 准备材料、宿主判断、验证应用 | [判断接口](references/judgment-interface.md)；实际入口 `scripts/judgment_handoff.py --help` |
| 编写领域判断或处理 prompt 与数据边界 | [prompt 方法](references/prompt-loading.md) |
| 选择质量检查、实际试用和成本记录 | [验收方法](references/acceptance-cases.md) |
| 确需独立审查或并行子 Agent | [宿主派发](references/host-dispatch.md) |
| 大结构填充、受限修订或复杂恢复 | [实现案例](references/implementation-walkthrough.md)、[高级隔离示例](assets/evidence-brief/SKILL.md)；不作为默认模板 |

## 1. 保留合同，追清真实步骤

写清用户给什么、拿走什么、怎样判定可用、不可改变的事实/证据、用户偏好与已授权动作。缺失材料怎样处理也属于合同。重构不能通过删输出、反例或验证步骤减少调用。

沿一次真实任务的输入→处理→输出→消费者追踪，查看代码或运行记录，不只按 Markdown 标题拆阶段。每个必要步骤记录一行：

`输入及语义参数 → 既有工具/脚本/宿主判断 → 输出 → 消费者 → 验证 → 失败后动作`

已有工作流的优化必须沿默认真实入口检查实际执行权：提供了脚本工具，不等于程序已经接管该步骤。区分数据处理、下一步调度、模型上下文准备和失败恢复；记录每个机械步骤是否仍须模型发起一次调用。具体检查见 [执行边界审计](references/execution-boundary-audit.md)。

还要逐项追踪批准要求是否进入任务和最终验收。展示计划应来自实际冻结合同；总数量、文件存在、worker 完成和总评分不能替代每项内容达标。用删掉一项、无关内容凑数及陈旧评审等缺陷注入验证最终交付会被阻止，见 [要求闭环审计](references/obligation-closure.md)。

短任务写几行即可。优先抽取重复明显、边界清楚或计算易错的一段，不先造通用工作流平台。

## 2. 固化稳定操作，参数化任务差异

优先复用同项目实现、现成连接器/CLI、标准库和已安装依赖。解析、精确去重、排序、计算、编号、引用组装、固定渲染与读写由程序完成。模型选择 ID 或返回允许字段的增量，程序复制原始事实并合并。

路径、来源、语言、列名、阈值、单位和模板等差异使用有默认值、合法范围与未知值处理的参数。语义相同不等于字符串相同；缺失字段的业务含义不能由解析器猜测。

实现保存到目标 Skill 的 `scripts/`，运行数据保存到本次任务目录。入口可从任意工作目录调用，资源相对脚本自身定位。外部命令用参数数组、明确工作目录、超时和返回检查。宿主专有连接器可由宿主读取并落盘，不强行包装成无法继承授权的 Python SDK。

## 3. 在必要位置加入判断接口

默认路径：

```text
prepare → 规则足够：直接 apply
        → needs_judgment：当前宿主读请求、写判断 → validate → apply → receipt
        → needs_input：记录缺口，补材料后重建请求
```

每个判断点说明问题、领域标准、必要材料与稳定 ID、允许返回的字段、不确定性出口和消费者。只要求受约束数据及必要理由，不要求完整内部推理，不接受任意可执行命令或源文本重抄。

跨文件交接绑定材料快照、目标、规则版本和影响语义的参数。程序检查字段、类型、ID、重复、请求绑定和业务不变量后应用。材料不足与“材料充分但无符合项”分开；结构通过不等于语义正确。

程序可从已知状态确定的分页、保存、编号、校验和阶段推进，应由默认入口直接执行，不只在提示词里要求模型调用工具。每个判断点只提供当前需要的 schema、证据和未决项；保存分块却仍逐轮重发完整工具集与历史，不算完成上下文优化。

少量判断由当前宿主完成，不新增模型调用。批量独立任务、无人值守、吞吐管理或确需独立审查时，才接真实可用的后端；保持相同业务数据合同，另管超时、响应包装、调用预算和错误。`needs_judgment` 只是控制权交还，不会自动启动模型。

## 4. 显式设计状态、分支和恢复

简单流程用普通函数、条件语句和必要的状态文件。只有多分支协调、跨会话等待和恢复逻辑确实值得时才评估 LangGraph；步骤多本身不是理由。

按需采用 `needs_judgment / needs_input / done / retryable_error / failed` 等状态，不要求全部实现。每个状态说明完成范围与下一动作。若提供 `next`，它必须只读；同输入重跑可预测，输出冲突不静默覆盖，输入或规则变化使受影响判断失效。哈希防误配，不证明来源真实性。

缺文件先补输入；坏 JSON 返回具体字段错误并限定修复次数；证据不足补材料或明确未完成；临时服务故障有限重试；未知程序错误保留诊断再修实现。不能把失败改为空结果或成功，不重跑无关成功步骤。持久化还需配套程序可判定的恢复位置、结果完整性校验和输入依赖失效规则；保存了一批 ID 后让模型重新猜流程，不等于可靠恢复。外部写入另用服务操作 ID、已有结果查询或幂等机制，重试计数不能防止重复副作用。

## 5. 写成日常可直接调用的 Skill

目标 `SKILL.md` 保留使用条件、输入与真实入口、参数选择、判断标准、错误处理和完成条件。将“编写脚本做某事”改成“调用已提供的入口”。日常执行读合同和本次判断材料，已有能力覆盖时不重新生成算法，也不先读全部源码。

新输入超出接口时区分缺参数、一次性适配和核心能力变化：前两者继续复用；确需维护时才读源码、修改并回归。不把临时文件名永久硬编码。

长领域规则放 references，可复制模板放 assets，算法以代码为准，不维护三份副本。生成的 Skill 直接说明用途和执行合同，不附设计来源宣传；领域证据与必要许可证保留。保持现有发现方式、UI 和权限字段，尊重指定安装位置。

## 6. 用质量和实际成本验收

先检查完整交付、事实/证据、约束和下游可用性，再看效率。运行真实入口和关键失败案例。含模型判断时，由宿主实际读取请求、写判断，并让程序消费；固定 JSON 只算程序测试。只有声称独立派发时才要求真实子 Agent、返回 ID 及对应产物。

重构用同一组代表性任务核对原合同，区分旧版实测、仅审查与未运行。记录任务中新写代码次数、全部宿主/子调用可取得的 token、调用和修复次数、端到端耗时及维护投入；缺数据写 `unavailable`。少量试跑只报实际值，不凭代码行数、调用减少或单次通过宣布效果改善。检查默认入口实际派发的 schema、上下文体积和机械性工具回合；让模型主动选择新工具的测试，不能证明默认流程已经迁移。重构已有系统时，至少验证受影响的真实入口及一个关键失败后的局部恢复；固定正确返回只验证程序合同，真实模型试跑另列输入性质和覆盖边界。

复杂创作器可用独立 Agent 做一次新请求的前向创建与使用，给原始材料和操作范围，不给预期答案。按 [验收方法](references/acceptance-cases.md) 查看实际文件，只修发现问题所在层。

## 完成条件

- 原合同保留，必要程序已保存，真实入口能产生下游可用的结果。
- 判断有准备、返回、验证和应用路径；失败、未决项、覆盖和恢复符合合同。
- 适用的格式、程序与内容检查实际执行；未测语义、依赖和成本分别说明。
- 按约定安装或同步并检查实际文件；交付绝对路径、行为变化、实际检查与限制。
